## 二、新增/修改文件详解

### 2.1 百度千帆智能 PPT API（D4 主方案，2026-08-15 实证）

> 用户提供 API（每日 10 次免费）与官方文档（桌面 `新建 文本文档.md`），密钥已写入 .env（`BAIDU_PPT_*`）。

**接口**：`POST https://qianfan.baidubce.com/v2/tools/ai_ppt/generate_ppt_by_outline`

| 项 | 内容 |
|---|---|
| 鉴权 | `Authorization: Bearer <bce-v3 密钥>`（.env `BAIDU_PPT_API_KEY`） |
| 必填参数 | `query_id`/`chat_id`（自编号即可，实测 1/1 可用）、`outline`（严格 Markdown）、`query`、`title`、`style_id`、`tpl_id`（102322 商务，官方示例） |
| 可选 | `gen_mode`（1=智能润色，2=严格依从）、`ai_info`（尾页 AI 标识） |
| 响应 | **SSE 流式**：`PPT生成中`×N（每页 `bd_ppt_json`）→ `PPT生成结束` → `PPT导出中` → `PPT导出结束`（`data.pptx_url` 下载地址） |
| 产物 | 37 页商务 PPT / 17MB（含设计配图），内容 AI 润色 |
| 耗时 | 全流程 ~20s |

**大纲格式约束**（官方文档，必须严格遵守）：
```
# 一级标题（# 空格）
* 二级标题（* 空格）
  * 三级要点（两个空格 + * + 空格）
```
- 至少一个一级标题；格式小问题百度自动修复，无法修复则报错。
- ⚠️ **坑**：`resource_url`/`custom_tpl_url` 传空字符串被拒绝（`resource_url not valid`）——不传即可。

### 2.2 `src/ai/ppt_baidu.py` 🆕 — 百度 API 封装

| 成员 | 说明 |
|---|---|
| `TEMPLATE_MAP` | 模板名 → 百度 (style_id, tpl_id)：business=102322（实测）；simple/tech 暂映射同款（**待模板接口确认 ID**） |

## 三、📖 阅读指南（建议顺序）

### 第 1 组：百度 API 实证（先看"为什么主方案是它"）

**Step 1｜`scripts/test_ppt_api.py`** — 百度 API 验证脚本
- 看什么：`build_outline`（百度 Markdown 大纲格式）；`call_generate`（SSE 解析 status 流转）；`download_pptx` + `verify_pptx`（zip/幻灯片校验）。
- 思考题：为什么百度方案效果碾压自研？（答：37 页 17MB 含设计配图 vs 本地 6 页纯文本——百度内置排版引擎+素材库；但受每日 10 次免费额度限制）。

### 第 2 组：后端分层（2–6）

**Step 2｜`src/ai/ppt_baidu.py`** — 百度封装
- 看什么：`outline_to_baidu` 三级格式转换；`generate_ppt` 的 SSE 解析（status 字段驱动状态机）；`download_pptx` 的 zip 校验。
- 思考题：为什么 query_id/chat_id 自编号即可？（答：实测 1/1 不影响效果，文档称"影响生成效果"是保守表述）；`resource_url` 为什么不能传空串？（答：服务端校验非法，不传字段即可）。

**Step 3｜`src/services/ppt_service.py`** — 业务层（最重要）
- 看什么：`generate` 的双方案降级（百度→本地）；状态机同步；`_get_owned` 归属校验。
- 思考题：为什么降级逻辑放 service 而不是 router？（答：router 薄原则——降级是业务决策，与 HTTP 无关）；为什么失败态编辑大纲后回草稿？（答：让用户改完可重新生成）。

### 第 3 组：前端（8）

**Step 4｜`front/safety/index.html` #/ppt 页** — PPT 工坊
- 看什么：任务列表渲染（状态徽章复用 hazard 的 badge 样式）；大纲编辑弹窗；`genPpt` 的 confirm 防误触 + 生成中提示。
- 思考题：为什么生成是同步阻塞而非 SSE 进度？（答：百度 API 本身就是一次 SSE 全流程，后端同步等待后返回最终状态；前端用 confirm + 按钮禁用防重复提交——P3 简化方案，演示足够）。

### 第 4 组：知识库增量（9）

**Step 5｜`knowledge_src/laws/` + `scripts/collect_kb.py --doc-type laws`** — 增量入库
- 看什么：稳定 ID 自动去重；`--doc-type` 只入指定类型；治理流程（条例逐行去重/水印清理）。

> 💡 心法（D4 版）：**PPT 模块 = 大纲是蓝图（LLM JSON）→ 转换是翻译（百度 Markdown 三级格式）→ 百度是主工厂（SSE 流式 + 智能润色）→ 本地是备胎（免费额度用尽）→ 文件是交付（/ppt-files 下载）**。主方案效果碾压但受配额限制，兜底方案保证演示零翻车——双方案互为保险。

## 五、今日踩坑记录

| 坑 | 现象 | 解法 |
|---|---|---|
| **resource_url 空串 400** | 传 `"resource_url": ""` → `resource_url not valid` | 不传该字段（body 里删掉） |
| **urllib 走代理 502** | Python urllib 访问 localhost:8000 报 502 | `build_opener(ProxyHandler({}))` 禁用代理（本机 7897 劫持，同 curl --noproxy） |
| **curl 中文 body 400** | git-bash curl POST 中文 JSON → `error parsing the body` | 用 Python urllib 发请求（编码可靠） |
| **uvicorn 实例 502** | 旧实例 PPT 代码半就绪时登录也 502 | 重启 uvicorn 加载最新代码 |
| **条例逐行重复** | PDF 转 md 每行出现两次（360→175 行） | 相邻重复去重脚本 + 条文完整性验证（46 条全在） |
| **JTG T3302 水印** | 「交通运输部信息浏览专用」×3 | 行级删除 |
| **中文文件名下载** | curl 编码乱码 0 bytes | Python `urllib.parse.quote` + 无代理下载（后端本身正常） |
| **patch 覆盖密钥** | 改 .env 时把真实 key 写成占位符 | 立即回滚恢复（教训：**含密钥行用最小替换，不整行重写**） |
| **下载 404（file_path 反斜杠）** | 前端 `split('/')` 分不开 Windows 路径 `ppt_files\xxx.pptx` → 整个路径当文件名 → 404 | 前端 `replace(/\\/g,'/').split('/').pop()` 兼容双分隔符（**注意 JS 源码 2 个反斜杠，Python 写入会转义，用 node --check 校验**） |
| **百度 API SSL EOF** | 用户端生成时 `SSL: UNEXPECTED_EOF_WHILE_READING` → 降级本地 | `urllib.build_opener(ProxyHandler({}))` 禁代理直连（本机 7897 劫持 HTTPS，同政务站经验） |

## 八、给队友的话

- **免费额度**：每日 10 次（BAIDU_PPT_DAILY_QUOTA），演示前确认剩余；失败自动降级本地，不必重试；
- **模板扩展**：拿到百度模板接口后只改 `ppt_baidu.TEMPLATE_MAP`，前后端零改动；
- **新增法规**：放 `knowledge_src/laws/` → 治理（重复/水印）→ `collect_kb.py --doc-type laws`（稳定 ID 自动去重）；
- **知识库重治理**：必须先清空 Chroma 集合再全量入库（D3 教训）。
