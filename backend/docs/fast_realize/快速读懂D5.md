## 二、新增/修改文件详解

### 2.1 引用来源阅读器（优化 1：AI 回答引用可点击查看原件）

> 背景：AI 问答底部引用标签原为纯文本，用户无法查看知识原文。现在点击标签即可跳转阅读治理后的 md 原件。

| 层 | 实现 | 说明 |
|---|---|---|
| `src/routers/kb.py` 🆕 | `GET /api/kb/doc?path=knowledge_src/laws/xxx.md` | 只读接口：白名单四类目录（laws/procedures/plans/cases）+ 扩展名 .md/.txt + resolve 前缀校验防路径穿越；`source` 字段含 `knowledge_src/` 前缀时自动剥除（D5 实测修复）；需登录 |
| `front/safety/index.html` | 引用标签改可点击（`tag-link` + `openKbDoc`）；新增 `#/kb-doc` 独立阅读页（`loadKbDoc` + `mdRender` 轻量 md→HTML 渲染器：标题/列表/引用/代码块/加粗，零外部依赖） | 路由 `qs.get('path')` 取文档路径 |
| `front/demo/index.html` | 引用标签同改；阅读器用**模态框**形态（`kb-reader` overlay） | demo 简洁版不引入路由页 |

**实测**：点击引用 → 跳转 `#/kb-doc` → 加载北京建筑施工安全操作规程全文（标题/段落/列表正确渲染）✅；demo 模态框加载国家防汛抗旱应急预案 29.8KB 正文 ✅；`../.env` 路径穿越 400 拦截 ✅。

### 2.6 消息类型丰富化（H08 升级：整改反馈→管理员 / 验收结果→安全员·管理员 / 最终处理→全员）

> 背景：原消息页只有「接收派发」一类消息（通知 JSON 无 type 字段，前端无法分类）。需求：① 收到整改反馈（管理员）② 验收结果（安全员、管理员）③ 上报隐患最终处理结果（管理员、安全员、普通用户）。

| 改动 | 说明 |
|---|---|
| `notification_service.py` | 通知 JSON 增加 **`type` 字段**：`assign`（派发→责任人）/ `rectify`（整改反馈→上报人+管理员）/ `accept`（验收结果→当事人+安全员/管理员）/ `final`（最终处理→全员）/ `general` 兜底；旧数据兼容（无 type 默认 general） |
| `hazard_service.py` | rectify：上报人收「待验收」+ **管理员收「整改反馈」**；accept：当事人收「验收结果」+ **安全员/管理员收「验收结果」**（当事人除外）+ **全员收「最终处理结果」** |
| `front/safety/index.html` | `loadNotifies` 改为**按 type 分组渲染**：NOTIFY_TYPES 映射（📋整改任务蓝 / ✍️整改反馈橙 / ✅验收结果绿 / 🏁最终处理紫 / 📢通知灰）+ 组标签含图标+数量徽章 + 消息左侧同色竖条 |

**验证脚本**：`scripts/verify_notify_types.py` 🆕（注册 上报人/责任人/安全员 → 上报 → 派单 → 整改 → 验收 → 逐角色断言 type）

**实测**（隐患 #133）：整改后管理员收到 rectify ✅；admin 验收后——安全员/管理员收 accept + final ✅、上报人/责任人收 accept（验收通过）+ final ✅；前端分组渲染「✅ 验收结果」「🏁 最终处理」✅。

**踩坑**：
- `TYPE_*` 常量定义在模块级，误用 `NotificationService.TYPE_RECTIFY`（类属性不存在）→ AttributeError 500 → 改 import 模块级常量；
- final 文案 `已{target}` 而 target 已是「已闭环」→ 「已已闭环」→ 去掉重复「已」；
- 注册接口默认 employee 角色，验证安全员场景需手动改 role=safety_officer。

测试数据已清理。
