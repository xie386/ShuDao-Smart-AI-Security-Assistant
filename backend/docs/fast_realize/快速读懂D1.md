## 一、项目简介

蜀道集团的传统安全管理依赖纸质/表格流转：隐患上报不及时、整改闭环难追踪、安全培训资料分散。本产品用 AI 技术把三件事线上化：

- 🚨 **隐患安全模块（H01–H08）**：隐患「上报 → 派单 → 整改 → 验收」全流程闭环，含图片、定位、等级分类、统计分析、消息通知；
- 🤖 **AI 助手模块（A01–A07）**：基于企业安全知识库的智能问答，**RAG 架构** + SSE 流式输出 + 回答引用来源 + 点赞/踩反馈；
- 📊 **PPT 工坊模块（P01–P08）**：输入主题 → AI 生成大纲 → 用户编辑 → AI 填充内容 → 3 套模板渲染 → 导出 `.pptx`。

核心理念 **「文档先行 + 分层后端 + RAG 增强」**：需求以 **H/A/P 编号** 贯穿五份文档；后端严格分层 `router → service → model/schema`；AI 回答必须基于企业知识库（结构感知分块 + 混合检索 + 重排压幻觉）。

> 一句话：把「纸质台账里的隐患」变成「线上闭环」，把「翻制度查规范」变成「问 AI 秒答」，把「手工做培训课件」变成「AI 一键生成」。

### 5.2 core 层

#### `src/core/config.py` — 全局配置（pydantic-settings）

| 配置分组 | 关键项 | 说明 |
|---|---|---|
| 应用 | `APP_NAME` / `APP_VERSION` / `DEBUG` | 基本信息 |
| 安全 | `SECRET_KEY` / `ALGORITHM=HS256` / `ACCESS_TOKEN_EXPIRE_MINUTES=1440` | JWT 基础（开发期 24h） |
| 数据层 | `DATABASE_URL`（mysql+mysqlconnector://root:123456@127.0.0.1:3306/shudao_safety）/ `REDIS_URL` | 本机开发值 |
| AI 模型 | `DEEPSEEK_*`（主）/ `AGNES_*`（降级）/ `QWEN_*`（视觉） | **模型名/地址全部可配，代码零硬编码** |
| 本地模型 | `EMBEDDING_MODEL_PATH`（bge-large-zh）/ `RERANKER_MODEL_PATH` / `EMBEDDING_DEVICE=cuda` / `RERANKER_DEVICE=cuda` | device 默认 **cuda**（用户决策） |
| 向量库 | `CHROMA_DIR=chroma` / `CHROMA_COLLECTION=safety_kb` / `RAG_TOP_K_RERANK=4` | Chroma 持久化 |
| LLM 参数 | `LLM_TIMEOUT=60` / `LLM_MAX_RETRIES=1` / `LLM_TEMPERATURE=0.7` | 调用策略 |

要点：`get_settings()` 用 `@lru_cache` 缓存，`settings` 为模块级单例；`.env` 文件未提交（gitignore），`.env.example` 是模板。

#### `src/core/db.py` — 数据库引擎与会话

| 对象 | 说明 |
|---|---|
| `Base(DeclarativeBase)` | 全部 ORM 模型的基类 |
| `engine` | `create_engine(DATABASE_URL, pool_pre_ping=True, pool_recycle=3600)`——断线自动重连、连接回收 |
| `SessionLocal` | 会话工厂（`expire_on_commit=False`，提交后属性仍可读） |
| `get_db()` | FastAPI 依赖：请求级会话，finally 自动关闭——**每个接口统一这么拿 db** |

#### `src/core/security.py` — 安全核心（bcrypt + JWT）

| 函数 | 签名 → 返回 | 说明 |
|---|---|---|
| `hash_password` | `(password: str) -> str` | bcrypt 哈希（自动盐），返回 str 入库 |
| `verify_password` | `(password, hashed) -> bool` | 校验；失败返回 False 不抛异常 |
| `create_access_token` | `(subject, role, expires_minutes=None) -> str` | JWT HS256，payload 带 `sub`/`role`/`exp` |
| `decode_access_token` | `(token) -> dict` | 校验+解析，无效抛 401 |
| `get_current_user` | `(credentials=Depends(_bearer)) -> {id, role}` | **依赖注入**：从 `Authorization: Bearer` 解析当前用户；其他模块加一行即可鉴权 |

设计要点：
- **不用 passlib**——全局 bcrypt 5.0.0 与 passlib 有已知兼容问题（读不到 `__about__`），直接调 bcrypt 库；
- `HTTPBearer(auto_error=False)` 手动处理空 token（返回统一 401 文案）；
- D2 的 RBAC（`require_roles`）在此文件扩展。

#### `src/core/redis_client.py` — Redis 连接池

| 函数 | 说明 |
|---|---|
| `get_redis()` | `@lru_cache` 单例；`redis.Redis.from_url(REDIS_URL, decode_responses=True)`——返回 str 免手动 decode |
| `ping_redis()` | 优雅探测：服务未启动返回 False（**不抛异常**），日志告警 |

要点：redis-py 是**懒连接**（import 不报错，首次命令才连）；本机 6379 当前未启动，`ping_redis()` 实测返回 False ✅；D2 起用于会话缓存/限流/站内消息。

### 5.3 models 层（6 模型 ↔ 6 表，全部 `db_verify.py` 列级对齐 ✅）

#### `src/models/user.py` — User

| 列 | 类型 | 说明 |
|---|---|---|
| id | int PK 自增 | 用户 ID |
| username | varchar(64) 唯一索引 | 登录名 |
| hashed_password | varchar(255) | bcrypt 哈希（**不存明文**） |

#### `src/models/hazard.py` — Hazard + HazardTimeline

Hazard（15 列，H01–H06 核心表）：

| 列 | 说明 |
|---|---|
| title / description | 隐患标题/描述 |
| level | enum(重大/较大/一般/轻微) |
| hazard_type / location | 类型/位置 |
| status | enum(待处理/处理中/待验收/已闭环/已驳回)——**状态机字段**（PRD） |
| reporter_id / assignee_id | 上报人/责任人（FK users，assignee 可空） |
| due_date | 整改期限（H04 派单） |

| rectify_measures / rectify_images | **H05 整改措施 + 整改后照片** |
| created_at / updated_at | `updated_at` 表无 ON UPDATE 触发器，由 ORM `onupdate=func.now()` 应用层维护 |

HazardTimeline（6 列）：`hazard_id`(FK) + `action`(上报/派单/整改/验收/驳回) + `operator_id` + `note` + `created_at`——H03 详情页的**处理进度时间线**。

#### `src/models/conversation.py` — Conversation + ChatMessage

- **Conversation**（4 列）：`user_id`(FK) + `title` + `created_at`——A02 会话管理；
- **ChatMessage**（7 列）：`conversation_id`(FK) + `role`(user/assistant/system) + `content` + **`references`**（回答引用来源，A06）+ `rating`（A07 点赞1/踩-1）+ `created_at`。
  - ⚠️ 坑：列名 `references` 是 SQL 保留字语境，ORM 属性用 **`refs = mapped_column("references", Text)`** 规避（属性名与列名分离）。

#### `src/models/ppt_task.py` — PptTask

8 列：`user_id`(FK) + `topic`(主题) + `outline`(大纲 JSON，P01/P02) + `template`(商务/简约/科技，P04) + `file_path`(.pptx 落盘路径) + `status`(enum 草稿/生成中/已完成/失败) + `created_at`——P03–P07 任务状态机。

#### `src/models/__init__.py`

统一导出 6 个模型（User/Hazard/HazardTimeline/Conversation/ChatMessage/PptTask）——其他模块 `from src import models` 即可用全部模型。

### 5.5 routers + services（认证三接口闭环）

#### `src/routers/auth.py` — 路由层（薄）

| 端点 | 方法 | 响应 | 说明 |
|---|---|---|---|
| `/api/auth/register` | POST | 201 UserOut | 注册，新用户固定 employee |
| `/api/auth/login` | POST | TokenResponse | 登录拿 JWT |
| `/api/auth/me` | GET | UserOut | 当前用户（`Depends(get_current_user)` 鉴权） |

#### `src/services/auth_service.py` — 业务层（厚）

| 方法 | 行为 |
|---|---|
| `register(db, data)` | 用户名查重 → 409；bcrypt 哈希；**role 硬编码 "employee"**；落库 |
| `authenticate(db, username, password)` | 用户不存在与密码错误**统一 401**（不泄露账号存在性） |
| `issue_token(user)` | 签发 JWT + 组装响应 |
| `get_by_id(db, user_id)` | 查用户，无则 404 |

**分层契约**：router 只做参数校验与路由；service 承载业务与安全规则；model 映射表；schema 定义形状。新模块照抄此三件套。

### 5.6 ai 层（P2 基建，全部 lazy-import）

#### `src/ai/llm_client.py` — 大模型客户端（DeepSeek 主 / agnes 降级）

| 成员 | 说明 |
|---|---|
| `_primary_client()` / `_fallback_client()` | 懒加载两个 OpenAI 客户端（不同 base_url/api_key），`timeout=60, max_retries=1` |
| `chat(messages, temperature)` | 非流式：DeepSeek 失败 → 日志告警 → **自动降级 agnes** |
| `chat_stream(messages, temperature)` | 流式：yield 增量文本；主模型中途失败同样切 agnes（A03 SSE 直接复用） |
| `_complete` / `_stream` | 底层封装（空内容抛错） |
| `llm_client` | 模块级单例（连接复用） |

实测：非流式 35 字 ✅、流式 33 字 ✅、主模型 502 → agnes 正常回答 ✅。

#### `src/ai/embeddings.py` — 本地嵌入（bge-large-zh）

| 成员 | 说明 |
|---|---|
| `model`（property） | lazy 加载 SentenceTransformer，`device=cuda`，打印维度 |
| `embed_documents(texts)` | 批量编码，`normalize_embeddings=True`（与 Chroma 余弦匹配），batch 32 |
| `embed_query(text)` | 单条查询，**自动加 bge 指令前缀** `为这个句子生成表示以用于检索相关文章：`（官方推荐，提升召回） |
| `embedding_model` | 单例 |

实测：cuda 加载 11.8s，1024 维，中文编码正常 ✅。

#### `src/ai/reranker.py` — 本地重排（bge-reranker-base）

| 成员 | 说明 |
|---|---|
| `model`（property） | lazy 加载 CrossEncoder（device=cuda） |
| `rerank(query, docs, top_k=4)` | (query, doc) 对打分 → 降序取 Top-k → `[(原文索引, 分数)]` |

实测：3.3s，Top-2 = [(0, 0.998), (2, 0.895)]，正确排除无关文档 ✅。

#### `src/ai/knowledge.py` — 知识库构建（Chroma + 分块）

| 成员 | 说明 |
|---|---|
| `get_collection()` | PersistentClient + `safety_kb` 集合（**cosine 空间，1024 维锁定**） |
| `split_law` | 法规按「第X条」切，章为父级元数据 |
| `split_procedure` | 规程按步骤编号/作业前中后切 |
| `split_plan` | 预案按预警/响应/处置/恢复阶段切 |
| `split_case` | 案例按经过/原因/教训字段切 |
| `SPLITTERS` | 四类目录名 → 分块函数映射 |
| `upsert_chunks(chunks)` | 分块 → **本地嵌入显式传向量** → upsert（id=uuid4，metadata 带 doc/doc_type/chapter/tags/source） |
| `build_from_dir()` | 扫描 `knowledge_src/{laws,procedures,plans,cases}/` → 分块 → 入库 → 统计 |

⚠️ **Chroma 过滤坑（实测）**：1.5.9 不支持 list 字段 `$in`/`$eq`（抛 ValueError）→ 多值 tags 过滤必须用 `$contains`；标量字段（doc/doc_type）用 `$eq`/简写。

## 十一、思考问题（理解自测）

1. 为什么注册接口"不接受 role 字段"比"接收后校验"更安全？（差在少一个攻击面）
2. JWT 里已经带了 role，为什么 /me 还要查一次数据库？（token 过期 vs 账号被改）
3. LLM 降级是怎么实现的？如果 agnes 也失败会怎样？（两层 try/except，最后抛出）
4. 为什么嵌入/重排模型要 lazy load？如果 main.py 顶层 import 会有什么后果？（拖慢启动、无 GPU 环境直接崩）
5. bge 查询为什么要加指令前缀？不加会怎样？（召回率下降，query 与 passage 训练不对称）
6. Chroma 里 tags 是 list，为什么不能用 `$in` 过滤？（1.5.9 抛 ValueError；多值字段用 `$contains`）
7. 如果换嵌入模型（如 bge-m3），除了改路径还要做什么？（维度变化 → 重建集合）
8. 隐患模块要"仅管理员可派单"，路由层应该怎么加校验？（读 payload["role"] 对比 PRD 角色表，D2 做 require_roles）
9. 为什么"应用不自动建表"？如果 AI 模块也需要新表，正确流程是什么？（P3 schema 统一管理）
10. 为什么 chat_messages.references 列在 ORM 里用 refs 属性？（SQL 保留字语境；属性名与列名可分离）
11. 为什么 hazards 的 updated_at 要配 `onupdate=func.now()`？（表无 ON UPDATE 触发器，需应用层维护）
12. db_verify.py 的定位是什么？它和 schema.sql、ORM 模型三者什么关系？（三者必须一致，脚本做守门员）
