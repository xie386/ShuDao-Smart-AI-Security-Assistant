# backend/docs 文档体系索引

> 本文是 `backend/docs/` 的**文档体系索引 + 全树导航**。新增文档前先看这里，再决定放哪个版本、哪一类。
> 编排规范已按本项目适配成文，放在本目录下：
> - [`版本文档规范.md`](版本文档规范.md) —— 同一版本内文档怎么编排、谁先谁后、谁是权威（四类分家 · 决策只进 Verdict · 规划文档四段式）
> - [`文件存放规则.md`](文件存放规则.md) —— 文件放哪（目录职责、不入库清单、tests 口径、巡检清单）

---

## 一、两级口径

| 目录 | 口径 |
|---|---|
| `docs/v1.0/` | **老版本归档**：v1.0 期的全部文档（任务书 / PRD / 架构 / AI 方案 / 里程碑 / D1-D5 快速读懂 / RAG 迭代评估报告 / 各模块计划书 / 知识库治理清单等）。统一口径＝**存放各种文档、不再逐一维护**，内部杂乱属正常，不迁移、不重排 |
| `docs/v2.0/` | **按四类编排**：`v2.0规划文档.md`（方案唯一权威）+ `research/`（调研信息）+ `Verdict/`（裁定唯一落点）+ `Done/`（实现记录与逐文件带读）；另有 `交接文档.md`（冷启动入口，不分进四类）与 `backups/`（改用户数据前的只读快照，该版本 git 提交后即删） |

## 二、v2.0 全树导航

```text
docs/v2.0/
├── v2.0规划文档.md        ★ 唯一权威：目录表（进度真值）+ 每个大点四段式
├── research/              调研期产物（信息堆砌，允许多方向与废案；实现期不通读）
├── Verdict/               实现分叉的裁定记录（决策类字眼只在这里）
├── Done/                  实现后沉淀（每大点两篇：实现记录 + 逐文件带读）
├── backups/              改用户数据前的只读快照（不入库）
└── 交接文档.md            版本冷启动入口（当下状态 + 下一步 + 纪律）
```

**编号规则**：`<NN>` = 该大点在规划文档里的序号，四类文件**共用同一编号与同名** —— 「规划 §00 ↔ `research/00-*` ↔ `Verdict/00-*` ↔ `Done/00-*`」一眼对上，不另建对照表。

## 三、每个大点的四段式（缺一段不算完整）

| 段 | 写什么 |
|---|---|
| ① 应对什么问题 | 现象 + **可复现证据**（数字、日志、`path:line`） |
| ② 功能 | 做完之后用户/系统多了什么（一句话能说清） |
| ③ 实现功能的技术方案 | 怎么落 + 来源标注（`research/NN-*.md` §X）；写到「换个会话照着能开工」的粒度 |
| ④ 实际实现的文档索引 | 指向 `Done/` 两篇；未开工写「未开始」 |

## 四、版本目录规则

- **整数版本**（`v1.0` / `v2.0` / …）= 大改：调研、方案、计划全进整数目录，且按四类编排。
- **小数版本**（`v2.5` 这类，若将来出现）= bug 与小优化：只放「问题 → 方案 → 结果」单篇，**不建四类子目录**。

## 五、与代码文档的分工

| 文档 | 管什么 |
|---|---|
| 本项目根 `README.md` | **代码阅读指南**（按「地基 → 基础设施 → AI 层 → 业务层 → 路由层 → 契约 → 工具 → 入口 → 脚本 → 测试 → 前端」的难度递进，每文件含「看什么 + 思考题」），以及项目简介、快速开始 |
| `backend/README.md` | 后端局部说明 |
| `deploy/README.md` | 部署说明 |
| `docs/v1.0/项目任务书-蜀道安全助手.md` | v1.0 的任务书与验收口径（v2.0 无新任务书，属组内优化迭代） |
| `docs/v2.0/` | v2.0 的调研、方案、裁定、实现记录 |
