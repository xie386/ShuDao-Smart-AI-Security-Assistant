## 0. 当前瓶颈排序（先治哪个）

基于 v1.0 实测的真实短板，按 ROI 排序：

| 排名 | 问题 | 证据 | 优先级 |
|------|------|------|--------|
| 1 | **多跳检索崩盘** | multi 全中率 8%、ALL 召回@K 0.66 未过 P2(0.80) | 🔴 最高 |
| 2 | **检索噪声大** | chunk 精确@K 仅 0.18~0.30 | 🟠 高 |
| 3 | 具体数字/条款错引 | 1 条确凿真幻觉（罚款 30-100万 vs context 20-50万） | 🟡 中 |
| 4 | **裁判模型不可靠** | 30 题标 20 条"幻觉"，核查绝大多数是误判 | 🟡 中（影响度量，不直接影响产品） |
| 5 | chunk 级指标名不副实 | expected_docs 是文档级标注 | ⚪ 低（标注工程） |

**关键判断**：忠实度报的 0.52 是裁判病不是模型病，真实约 0.80~0.88。**别在"降幻觉"上过度投入**，主线是检索侧（#1/#2），生成侧只做成本最低的"引用锚定+数字治理"即可。

## 1. 多跳检索 —— MMR + 多子查询聚合 🔴

**状态**：✅ 已实现（2026-08-19，落 `src/ai/rag.py`），待测（需后台跑 `--no-rewrite` 拿 v2.0 实测）
**目标**：multi 全中率 8%→≥40%，ALL 召回@K 0.66→≥0.80

### 1.1 多子查询分解 + 文档级聚合（专治多跳）
- 对多跳/复合问题，LLM 拆 2~3 个子查询（复用 `rewrite_query`，但**每个子查询各走完整检索链路**，不是只改写法）
- 各子查询独立做 稠密+稀疏 → RRF → 重排，得各自 Top-N
- **按 `doc` 聚合去重**：每个子问题至少贡献 1 份文档 → 直接抬 multi 全中率下限（之前单查询在全局分数里竞争，同主题文档互相挤掉）
- 聚合后再 MMR 去重，取 Top-4 喂 LLM
- ⚠️ 配额上限：子查询 A、B 都命中 docX 时 docX 占两席会挤掉其它期望文档，可加"每 doc 最多 1 席"

### 1.2 MMR 多样性重排（专治噪声 + 串味）
在 `FUSE_TOPK=30` 候选上做 Maximal Marginal Relevance：
```
score_i = λ·rerank_score_i − (1−λ)·max_j∈selected sim(i, j)
```
- `λ=0.7`（保相关性为主；若单跳精确率掉则往 0.8 提）
- 相似事故案例不再连续排前，模型读到差异化来源，串味概率下降
- 文档级去重已在 `parent_text` 去重里，MMR 做**语义级**去重更准

### 1.3 验证项
- 核对 `embeddings.py`：生成侧 `HuggingFaceEmbeddings` 是否对 query 加 `EMBEDDING_QUERY_PREFIX`（bge 必需，常见遗漏）

## 2. 检索噪声治理 🟠

**状态**：✅ 部分实现（MMR 已在源头打散同质块，落 `src/ai/rag.py`）；法规父块动态收缩⏳ 待做
**目标**：chunk 精确@K 0.25→≥0.45

- **现状**：K=10 召回块里仅 1/4~1/3 来自期望文档。注：真正喂 LLM 的是 `RAG_TOP_K_RERANK=4`（前 4），评测按 K=10 算精确率，所以生成质量未必像数字那么糟
- **手段**：MMR（#1.2）已在源头打散同质块；若精确率仍低，下调 `RAG_TOP_K_RERANK` 或加强重排阈值
- **法规父块动态收缩**（v1.0 不足 #4）：父块由"整章"改"命中条 ± 相邻 2 条"，单父块上限 ~1500 字符，避免稠密章挤爆 context、让 Top-4 能容纳更多不同文档

## 3. 生成侧 —— 引用锚定 + 数字治理 🟡

**状态**：✅ 已实现（2026-08-19，落 `prompt/prompts.yml` 的 `safety_qa` 第 4 条输出约束），待测
**目标**：消除具体数字/条款错引（唯一确凿的真幻觉类型）

在 `safety_qa` 系统提示词追加硬约束（不改业务意图）：
> 回答中每一条事实性结论必须对应 `[来源: xxx]` 标注；凡 context 未出现的具体事故名称、日期、数据、条款号，一律不得写入，标注"依据现有资料无法确认"。严禁把不同来源的案例细节混写。

- 配合 v1.0 已实现的 sources 引用落库（A06），形成"检索多样性 → 引用可控"闭环
- 这一条同时让忠实度变得**可测量**（强迫挂来源，裁判好判）

## 4. 裁判可靠性 —— 收紧 judge prompt 🟡

**状态**：待改 `scripts/rag_metrics.py` 的 `_FAITHFULNESS_TMPL`
**目标**：拿到接近真实的忠实度，v2.0 评估才有可比依据

### 4.1 已验证的误判类型（30 题里 20 条"幻觉"的拆解）
| 类型 | 例子 | 处理 |
|------|------|------|
| 归纳/结构句 | "主要原因可归纳如下"、"事故发生单位概况" | 移出"claim"分母 |
| 领域通用常识 | "无证上岗是高处坠落原因"、"责任分全部/主要/同等" | 移出分母（白名单或 LLM 预判） |
| context 内逐字内容被漏判 | "临边洞口设防护栏杆…" | 要求裁判做近义/包含匹配，非严格字符串 |
| **确凿错引** | 罚款 30-100万 vs context 20-50万 | **保留为 TP**，重点治理 |

### 4.2 具体改法
- `_FAITHFULNESS_TMPL` 增加：忽略归纳句/过渡句；领域常识性陈述不计为未支撑；具体实体/数字要求**近义匹配**而非严格子串；明确"数字、条款号、事故名必须能在 context 找到对应出处，否则算幻觉"
- 相关性模板补：拒答/空答不得判 1.00（v1.0 发现相关性对拒答过宽松）
- 改完重跑 `--limit 30`，预期忠实度回到 ~0.80 区间，与人工估算对齐

## 5. 标注工程（低优先级，v3.0）⚪

- **chunk 级指标名不副实**：`expected_docs` 是文档级标注，所以 `chunk_recall_at_k` 实际=文档级召回。要把标注细化到**章节粒度**才名副其实
- **`answer_correctness` 永久 N/A**：200 题无 `expected_answer`。人工补标后该指标自动生效（代码无需改）。**不能**用 context 让 LLM 自动生成参考答案（自证正确）
- 补一组 `--no-rewrite` vs 开改写的 A/B 抽样，量化查询改写增益
