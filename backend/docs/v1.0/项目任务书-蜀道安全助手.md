# 蜀道安全助手项目 - 任务书

## 一、项目概述

### 1.1 项目背景

蜀道集团作为大型交通建设企业,安全生产管理是核心业务之一。本项目旨在通过AI技术赋能传统安全管理流程,打造一个集隐患排查、智能问答、在线考试于一体的智能化安全管理平台。

### 1.2 项目目标

构建一个企业级的"蜀道安全助手"Web应用,实现以下三个核心模块:

- **隐患安全模块**: 安全隐患的上报、跟踪、整改闭环管理
- **AI助手模块**: 基于大语言模型的智能安全问答与知识检索
- **考试工坊模块**: 安全知识在线考试与培训测评

### 1.3 技术栈要求

| 层级   | 技术选型                                                |
| ---- | --------------------------------------------------- |
| 前端   | Vue3 + TypeScript + Element Plus / Vite             |
| 后端   | Spring Boot 3.x + MyBatis Plus / 或 Node.js + NestJS |
| 数据库  | MySQL 8.0 + Redis                                   |
| AI集成 | 国内大模型API(文心一言/通义千问/智谱等)                             |
| 部署   | Docker + Nginx                                      |

## 二、模块功能需求

### 模块一: 隐患安全管理

#### 2.1 功能清单

| 编号  | 功能点  | 优先级 | 说明                         |
| --- | ---- | --- | -------------------------- |
| H01 | 隐患上报 | P0  | 支持文字描述、图片上传、位置定位、隐患等级分类    |
| H02 | 隐患列表 | P0  | 分页展示、多条件筛选(状态/等级/类型/时间)、排序 |
| H03 | 隐患详情 | P0  | 完整信息展示、处理进度时间线             |
| H04 | 隐患派单 | P0  | 指派责任人、设置整改期限               |
| H05 | 整改反馈 | P0  | 责任人提交整改措施、整改后照片            |
| H06 | 隐患验收 | P1  | 审核人验收通过/驳回                 |
| H07 | 统计分析 | P1  | 隐患类型分布、整改率、趋势图表            |
| H08 | 消息通知 | P2  | 站内消息/邮件通知相关处理人             |

#### 2.2 隐患等级定义

- **重大隐患**: 可能导致重大安全事故,需立即整改
- **较大隐患**: 可能导致较大安全事故,限期整改
- **一般隐患**: 一般性问题,常规整改
- **轻微隐患**: 轻微问题,建议整改

#### 2.3 隐患状态流转

```
待处理 → 处理中 → 待验收 → 已闭环
                ↓
              已驳回 → 重新处理
```

### 模块二: AI智能助手

#### 2.4 功能清单

| 编号  | 功能点  | 优先级 | 说明                   |
| --- | ---- | --- | -------------------- |
| A01 | 智能问答 | P0  | 基于安全规范/制度的自然语言问答     |
| A02 | 会话管理 | P0  | 历史会话列表、新建会话、删除会话     |
| A03 | 流式输出 | P0  | SSE流式返回AI回答,提升用户体验   |
| A04 | 快捷提问 | P1  | 预设常见问题快捷入口           |
| A05 | 知识检索 | P1  | RAG架构,基于企业安全知识库的精准检索 |
| A06 | 回答引用 | P1  | 展示回答引用的知识来源          |
| A07 | 点赞/踩 | P2  | 用户反馈机制,用于优化AI回答质量    |

#### 2.5 技术要求

- 支持上下文多轮对话(至少5轮)
- 回答需基于企业安全知识库,避免幻觉
- 敏感词过滤与安全审核
- 并发支持 ≥ 50 QPS

#### 方向A: 安全讲座PPT智能制作

##### 2.6 功能清单(A方向)

| 编号  | 功能点  | 优先级 | 说明                   |
| --- | ---- | --- | -------------------- |
| P01 | 主题输入 | P0  | 输入讲座主题/关键词,AI自动生成PPT大纲 |
| P02 | 大纲编辑 | P0  | 支持手动调整大纲结构、增删章节 |
| P03 | PPT生成 | P0  | 根据大纲自动生成PPT,包含封面、目录、内容页、结尾页 |
| P04 | 模板选择 | P1  | 提供多种PPT模板风格(商务/简约/科技等) |
| P05 | 内容填充 | P0  | AI自动填充每页内容,包括文字要点、配图建议 |
| P06 | 在线预览 | P1  | PPT在线预览,支持翻页查看 |
| P07 | 导出下载 | P0  | 支持导出.pptx格式文件 |
| P08 | 手动编辑 | P2  | 支持在线编辑单页内容、替换图片 |

##### 2.7 技术要求(A方向)
- 使用python-pptx或类似库生成PPT文件
- AI负责内容生成和结构组织
- 模板需至少包含3套不同风格
- 生成的PPT需符合企业演示规范
- 支持中文字体正常显示

##### 2.8 PPT内容规范
- 封面: 标题、副标题、日期、制作单位
- 目录: 清晰的结构导航
- 内容页: 每页要点≤5条,文字精炼
- 配图: 与内容相关的安全主题图片
- 结尾页: 总结语、联系方式/致谢

#### 方向B: 考试工坊考题智能制作

##### 2.9 功能清单(B方向)

| 编号  | 功能点  | 优先级 | 说明                   |
| --- | ---- | --- | -------------------- |
| E01 | 题库管理 | P0  | 题目CRUD、支持单选/多选/判断/填空 |
| E02 | AI出题 | P0  | 输入知识点/难度,AI自动生成考题 |
| E03 | 试卷生成 | P0  | 手动组卷 + AI智能组卷两种模式 |
| E04 | 在线考试 | P0  | 倒计时、自动保存、防切屏检测 |
| E05 | 自动阅卷 | P0  | 客观题自动评分、成绩单生成 |
| E06 | 考试记录 | P1  | 历史考试查询、错题回顾 |
| E07 | 统计分析 | P1  | 考试通过率、错题排行、知识点掌握度 |
| E08 | 题目审核 | P1  | 管理员审核AI生成的题目,确保准确性 |

##### 2.10 技术要求(B方向)
- AI根据知识点自动出题,支持配置难度等级(简单/中等/困难)
- 题目需包含正确答案和详细解析
- 支持批量导入/导出题目(Excel格式)
- AI出题准确率需≥80%(经人工审核)

##### 2.11 考试规则
- 考试时间可配置(30/60/90分钟)
- 支持防作弊: 切屏超过3次自动交卷
- 成绩≥60分为合格,可配置合格线
- 考后展示正确答案与解析

### 3.3 文档质量标准

- 产品概述与背景说明
- 用户角色定义(管理员/安全员/普通员工)
- 完整的功能需求描述

- 页面原型图(手绘/Figma/Axure均可)
- 非功能性需求(性能/安全/兼容性)

每个接口必须包含:

```
- 接口名称
- 请求URL
- 请求方法(GET/POST/PUT/DELETE)
- 请求头要求
- 请求参数(类型、必填、说明)
- 响应体结构
- 成功/失败示例
- 错误码说明
```

#### 架构设计文档标准

- 系统整体架构图
- 技术栈选型及理由
- 模块划分与职责
- 数据流向图

## 四、企业级项目标准要求

### 4.1 代码规范

- 前端: 遵循 ESLint + Prettier 规范
- 后端: 遵循阿里巴巴Java开发手册 / NestJS最佳实践
- Git提交: 遵循 Conventional Commits 规范
  
  ```
  feat: 新增隐患上报功能
  fix: 修复考试倒计时bug
  docs: 更新接口文档
  ```

### 4.2 项目结构规范

```
project-root/
├── docs/                    # 项目文档
│   ├── PRD.md              # 产品需求文档
│   ├── API.md              # 接口文档
│   ├── ARCHITECTURE.md     # 架构设计文档
│   ├── AI_SOLUTION.md      # AI技术方案
│   └── DATABASE.md         # 数据库设计文档
├── frontend/               # 前端项目
│   ├── src/
│   │   ├── api/           # 接口请求
│   │   ├── components/    # 公共组件
│   │   ├── views/         # 页面组件
│   │   ├── router/        # 路由配置
│   │   ├── store/         # 状态管理
│   │   └── utils/         # 工具函数
│   └── package.json
├── backend/                # 后端项目
│   ├── src/
│   │   ├── controller/    # 控制器
│   │   ├── service/       # 业务逻辑
│   │   ├── model/         # 数据模型
│   │   ├── middleware/    # 中间件
│   │   └── config/        # 配置
│   └── package.json / pom.xml
├── database/               # 数据库脚本
│   ├── schema.sql         # 建表语句
│   └── init_data.sql      # 初始化数据
└── docker/                 # 部署配置
    ├── Dockerfile
    └── docker-compose.yml
```

### 4.3 安全要求

- 用户密码必须加密存储(BCrypt)
- 接口需做Token鉴权(JWT)
- SQL注入防护
- XSS防护
- 文件上传需做类型和大小校验
- 敏感操作需记录操作日志

### 4.4 性能要求

- 页面首屏加载时间 ≤ 2秒
- API响应时间 ≤ 500ms(P95)
- 支持并发用户数 ≥ 200
- AI问答响应时间 ≤ 3秒(首字)

### 4.5 测试要求

- 核心业务逻辑单元测试覆盖率 ≥ 60%
- 关键接口需有集成测试
- 前端核心组件需有单元测试
- 提交前需通过Lint检查
