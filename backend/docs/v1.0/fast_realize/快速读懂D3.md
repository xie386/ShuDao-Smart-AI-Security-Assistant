## 二、新增/修改文件详解

### 2.1 知识库数据治理（scripts/govern_html.py，两轮迭代）

| 机制 | 说明 |
|---|---|
| 容器选择器 | TRS/拓尔思 CMS 通用容器：`UCAP-CONTENT` > `pages_content` > `TRS_UEDITOR` > `trs_editor_view` |
| **全页收集兜底（二轮修复）** | 无容器命中时收集**全部 p/h1-h3/li**（噪声词过滤）——不依赖容器结构，适配 **table 布局**政务站（hcq.gov.cn 正文在 td 中） |
| 噪声词表 | 首页/收藏/打印/无障碍/长者助手/走进惠城/政务公开/粤公网安备/网站标识码/备案号/邮编…（**p 与 li 都过滤**） |
| 结构保留 | h1-h3 → `#/##/###`，p → 段落，li → 列表（利于结构感知分块） |
| 2000 字阈值 | 正文 <2000 字标记 `suspect`（正文可能在附件 docx/pdf 中） |
| manifest 回填 | title / extract_status / extract_chars / md_path |

**治理迭代记录**：
1. **一轮**：密度法 fallback（p 文本总长最大容器）→ cases 污染 89% → 0，但**部分页面选中 footer**（1cb44b 正文被截成 81 字）；
2. **二轮**：table 布局下正文不在 div 中 → 放弃容器密度法，改**全页 p/h/li 收集** → 1cb44b 恢复 6313 字，cases 入库块数 557 → 953。

### 2.2 知识库入库（src/ai/knowledge.py + scripts/collect_kb.py）

| 机制 | 说明 |
|---|---|
| 只扫 `.md`/`.txt` | 四类子目录，跳过 <2000 字节（治理 drop 标记） |
| **稳定 ID**（§4.5） | `doc_type\|doc\|chapter\|article_no\|文本前64字 → sha1[:16]`，重跑 upsert 覆盖去重 |
| **父子分块**（§4.3） | 子块入库做向量检索；`metadata.parent_text` 存父块完整文本喂 LLM |
| 批量嵌入+一次 upsert | 整库嵌入约 10 分钟（GPU）+ Chroma 写入约 10 分钟 |
| **--doc-type 增量** | `collect_kb.py --doc-type cases` 只入库指定类型 |

**D3 实测**：治理二轮后全量入库 **2256 块**（laws 230 / procedures 95 / plans 978 / cases 953）。

⚠️ **重治理后必须先清空集合再入库**：稳定 ID 基于内容哈希，治理后文本变化 → 新 ID → upsert 是**新增**而非覆盖，旧污染块会残留。

### 2.3 混合检索（src/ai/rag.py，D3 核心）

```
用户问题
  ├─ 稠密检索：langchain_chroma 向量 Top-20（bge-large-zh）
  ├─ 稀疏检索：BM25 Top-20（jieba 分词，条款号/专业术语精准命中）
  ├─ RRF 融合：score = Σ 1/(60+rank)，取 Top-20 进重排
  ├─ bge-reranker-base 交叉编码精排 → Top-4
  └─ 父块注入：命中子块 → 取 parent_text 完整章节 → 拼 context（带 [来源: 文档#章节] 标注）
```

| 组件 | 实现要点 |
|---|---|
| `_load_corpus()` / `_get_bm25()` | 双 `@lru_cache`：Chroma 全量语料 + BM25 索引（进程内缓存） |
| `_retrieve_candidates(q)` | 单查询两路召回 + RRF（不重排，供多路合并） |
| **`rewrite_query(q)`** | LLM 扩写 2-3 个子查询（prompts.yml query_rewrite 场景）；失败退化原问题；实测 8-48s（API 波动） |
| **`hybrid_retrieve(q, top_k, use_rewrite)`** | 改写后多路子查询合并候选（去重、上限 FUSE_TOPK×3）→ 统一重排 → 父块注入；`RAG_QUERY_REWRITE` 开关 |

**输出约定**：`context`（父块 + `[来源: 文档#章节]` 标注 → 注入 safety_qa 模板）+ `sources`（`[{doc, doc_type, chapter, article_no, source}]` → 落库 `ChatMessage.refs`，A06）。

### 2.4 问答 RAG 接入（src/routers/chat.py 改造）

```
POST /api/chat（SSE 流式）
  取/建会话 → 存 user 消息 → build_history
  → hybrid_retrieve(question) → context + sources        ★ RAG 接入点

```

### 第 2 组：入库（3）

**Step 3｜`src/ai/knowledge.py` + `scripts/collect_kb.py`** — 分块与入库

### 第 3 组：混合检索（4–5，D3 核心）

**Step 4｜`src/ai/rag.py`** — 混合检索编排（最重要）
- 看什么：`hybrid_retrieve` 全流程；`_retrieve_candidates`（单查询两路+RRF）；`rewrite_query`（LLM 改写 + 宽容 JSON 解析 + 失败退化）；双 lru_cache。
- 思考题：为什么改写失败要退化原问题？（答：检索不能因改写故障而阻断）；为什么多路子查询候选要按文本去重？（答：同一子块被多查询命中，去重避免重复）；`RAG_QUERY_REWRITE=False` 时？（答：退化为单查询两路检索，省一次 LLM 调用）

### 第 4 组：前端（6–7）

**Step 6｜`front/safety/index.html`** — 完整前端 SPA（川蜀风）
- 看什么：设计系统变量（朱砂红/印章金/宣纸米白）；hash 路由（`#/hazards/new` 的 `param==='new'` 分支）；`renderActions` 权限矩阵；`pendingFiles` 文件引用保留；fetch SSE 流式解析（ReadableStream 按 `\n\n` 分帧）。

## 四、今日关键决策

| 决策 | 内容 | 理由 |
|---|---|---|
| **全页收集替代密度法** | 无 TRS 容器时收集全部 p/h/li（噪声过滤） | table 布局政务站正文在 td 中，密度法选中 footer 丢正文（实测 1cb44b 81 字） |
| **数据治理前置** | 采集 → govern_html → 清空集合 → 重新入库 | 带导航污染的块直接拉低检索质量 |
| **FUSE_TOPK 12 → 20** | 融合候选放宽进重排 | 预案类 2 题从失败转命中 |
| **查询改写默认开启** | `RAG_QUERY_REWRITE=True`，失败退化原问题 | §5.4 口语提问召回提升；实测 8-48s（API 波动），可配置关闭 |
| **重治理后清空集合** | `col.get()['ids']` 全量 delete 再入库 | 稳定 ID 基于内容，旧污染块残留 |
| **A07 归属校验在 service** | rate_message 校验消息→会话→用户 | 数据级权限（router 拿不到数据） |
| **前端独立 front/ 目录** | 前端代码放项目根 front/，后端 FRONT_DIR 静态托管 | 用户规范：前端不塞 backend/ |
| **权限矩阵收窄** | 派单/验收仅 admin；安全员=上报/整改（仅被派单） | 用户标准：防止安全员验收自己整改的隐患 |
| **pendingFiles 保留文件引用** | 上传后 input.files 清空，AI 识别改用 pendingFiles[0] | 修复"上传后提示请先选择图片" |
| **qwen 冷启动兜底** | vision max_retries=1 + 前端 120s AbortController | 专属 MaaS 实例空闲休眠，首次调用 185s 超时 |
| **golden QA 是守门员** | 新增问答场景必须同步补 QA 题 | 参数调优有数据依据，防回归 |

## 五、今日踩坑记录

| 坑 | 现象 | 解法 |
|---|---|---|
| table 布局容器漏检 | 密度法选中 footer，1cb44b 正文 81 字（原 6313） | 全页 p/h/li 收集兜底（二轮治理） |
| li 分支漏过滤 | 导航词只过滤 p | `li` 也过 NOISE_WORDS |
| Chroma 空 where | `col.delete(where={})` 抛 "Expected where to have exactly one operator" | 改用 `col.get()['ids']` 批量删除 |
| 重入库旧块残留 | 稳定 ID 基于内容哈希，治理后文本变 → 追加 | 先清空集合再入库 |
| 改写首次慢 | rewrite_query 首次 48.7s（二次 8.5s） | API 冷启动/波动；失败退化原问题兜底 |
| 入库慢 | 2256 块嵌入+写入约 20 分钟 | 正常（1024 维批量）；GPU 满载即非卡死 |
| 重构删函数 | rag.py 重构时误删 `_rrf_fuse` | import 即时报错，补回（教训：重构后先 import 验证） |
| **前端路由 bug** | `#/hazards/new` 被解析成 path=hazards+param=new，走列表分支 | 路由判断加 `param === 'new'` 分支（在列表分支之前） |
| **上传后 AI 识别误报** | 上传图片后点识别提示"请先选择图片" | input.files 清空丢引用 → pendingFiles 数组保留 File |
| **qwen 专属实例冷启动** | 首次视觉识别 185s 超时（3 次重试），实例唤醒后正常 | max_retries=1 + 前端 120s 超时兜底 |
| **无头浏览器 alert 阻塞** | 实测时 alert() 弹窗卡页面 | 测试环境用 console.click() 触发替代 |
| **browser ref 失效** | headless 下 ref 点击偶发不触发 | console 直接调用 `.click()` 验证 |
| 代理 502（延续） | 政务站走代理 502 | fetch_kb `trust_env=False` 直连 |

## 八、给队友的话

- **知识库增量流程**：新文档放 `knowledge_src/<doc_type>/` → `govern_html.py`（htm 才需要）→ `collect_kb.py`（稳定 ID 自动去重；`--doc-type` 只入指定类型）；
- **改了分块/检索参数**：跑 `scripts/eval_qa.py --topk 4` 看 Recall——QA 集是守门员，新增问答场景请**同步补一条 golden QA**；
- **检索质量问题排查顺序**：先查知识覆盖 → 再查检索链路（dense/sparse 哪路空）→ 最后调参数（FUSE_TOPK/RRF_K/改写开关）；

- **隐患标注图**：视觉接口返回的 `boxes_url` 是后端用 `src/utils/boxes.py` 生成的标注图（画框逻辑勿在前端重写）；坐标排查顺序 = 模型 → vision.py → 路由 → 前端渲染；
- 混合检索/重排必须走 `src/ai/rag.py` 入口，不要另起炉灶；
- A07 前端对接：消息列表带 `rating` 字段，点赞/踩调 `POST /api/messages/{id}/rating`。
