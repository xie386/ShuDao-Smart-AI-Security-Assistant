## 二、新增文件详解

### 2.1 图片上传（H01/H05 共用）

#### `src/utils/files.py` — 上传校验与落盘

| 函数 | 说明 |
|---|---|
| `validate_and_save(file) -> url` | 扩展名白名单 → MIME 双校验 → 大小 ≤10MB → **uuid 重命名落盘** → 返回 `/uploads/xxx.jpg` |

安全设计（ARCHITECTURE §6）：白名单 jpg/jpeg/png/webp；扩展名与 MIME **双校验**（防伪造）；uuid 命名防路径穿越/重名覆盖；不信任用户文件名。

#### `src/routers/uploads.py` — 上传接口

`POST /api/uploads/image`（需登录，`Depends(get_current_user)`）→ `{url, message}`。
- H01 上报图 / H05 整改照共用；返回的 url 填入 `hazard.image_urls` / `rectify_images`。
- `src/main.py` 挂载 `StaticFiles("/uploads")` 提供访问。

⚠️ **坑（实测）**：`StaticFiles(directory=...)` 在**导入时**就要求目录存在——mkdir 必须放模块级（lifespan 里太晚），否则 `RuntimeError: Directory 'uploads' does not exist`。

### 2.2 H07 统计分析

#### `src/schemas/stats.py` + `src/services/stats_service.py` + `src/routers/stats.py`

`GET /api/stats/hazards`（需登录）→ `HazardStatsOut`：

| 字段 | 含义 |
|---|---|
| total / pending | 总数 / 未闭环数 |
| by_level | 重大/较大/一般/轻微 分布 |
| by_type | 类型分布 Top-10（NULL 归"未分类"） |
| rectify_rate | 整改率 = 已闭环/总数（0~1） |
| trend | 近 7 天每日 created + closed（按日期 group_by） |

实现要点：`func.count()` + `group_by` 聚合，**不加载全表**；空表返回完整结构（total=0、rate=0、7 个趋势点）——前端无需判空分支。

### 2.3 H08 消息通知（Redis 队列）

#### `src/services/notification_service.py`

| 方法 | 行为 |
|---|---|
| `push(user_id, message) -> bool` | rpush 到 `notify:{user_id}`；Redis 不可用 → 记日志返回 False |
| `list_for(user_id, limit=50)` | lrange 取最近 N 条（最新在末尾） |
| `count(user_id)` | 队列长度（未读数） |
| `clear(user_id)` | 删除队列 |

`GET /api/notifications`（需登录）→ `{total, items, unread}`；`DELETE /api/notifications` 清空。

**优雅降级（实测）**：Redis 未启动时接口返回空列表（200），不 500。⚠️ 后续隐患流转（派单/整改/验收）时在 service 里调 `push()` 通知相关人。

### 2.6 隐患模块（H01–H06，P1 线）

RBAC 依赖工厂：角色不在白名单抛 403。用法 `Depends(require_roles("admin", "safety_officer"))`——派单/验收的权限闸门。

#### `src/schemas/hazard.py` — 隐患契约

| Schema | 关键约束 |
|---|---|
| HazardCreate | title 2-128、description ≥5、level 四级正则、image_urls 列表 |
| AssignRequest | assignee_id 必填、due_date 可选（H04） |
| RectifyRequest | rectify_measures ≥5、rectify_images 列表（H05） |
| AcceptRequest | approved 必填（True=通过 False=驳回）、note 可选（H06） |
| HazardOut / HazardDetailOut(+timeline) / HazardListOut | 响应模型 |

#### `src/services/hazard_service.py` — 状态机核心

**状态流转表**（`VALID_TRANSITIONS`，非法流转 400）：
```
待处理 →(派单)→ 处理中 →(整改)→ 待验收 →(通过)→ 已闭环
                               └─(驳回)→ 已驳回 →(重新派单)→ 处理中
```

| 方法 | 行为 |
|---|---|
| `create` | H01 上报：status=待处理 + 时间线「上报」 |
| `list_hazards` | H02：分页 + 状态/等级/类型/时间筛选 + 4 种排序 + mine |
| `detail` / `timeline` | H03：详情 + 时间线 |
| `assign` | H04：校验流转→设责任人/期限→处理中→时间线「派单」→**通知责任人** |
| `rectify` | H05：**责任人/admin 才可**→待验收→时间线「整改反馈」→**通知上报人** |
| `accept` | H06：admin/安全员→已闭环/已驳回→时间线→**通知双方** |

权限顺序注意：**RBAC（router 层）→ 业务权限（assignee 校验）→ 状态机校验**——非责任人会先 403，非法流转对 admin 才显现 400。

#### `src/routers/chat.py` — SSE 核心

`POST /api/chat`（**sync def** + StreamingResponse）：
```
取/建会话 → 存 user 消息 → build_history → render(safety_qa) → llm_client.chat_stream
  → yield "data: {json delta}\n\n" 逐块推送 → 流结束存 assistant → yield "data: [DONE]"
```

⚠️ 两个关键设计（实测验证）：
1. **SSE 生成器内用独立 `SessionLocal()`**——`get_db` 依赖的会话随响应关闭，流结束后已不可用（assistant 落库放 finally）；
2. **RAG 未接入时幻觉抑制已生效**：retrieved_context 为空 → 模型回答"依据现有资料无法确认"（实测），D3 接知识库后自动有内容。
