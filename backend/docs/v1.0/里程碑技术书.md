## 4. 后端 + AI 部署重点（本里程碑重心）

### 4.1 后端核心
- **分层**：`router`(校验/路由) → `service`(业务/事务) → `model`(ORM) → `schema`(契约)，横切能力走 `middleware`(JWT/CORS/限流/日志)。
- **状态机**：隐患 `待处理→处理中→待验收→已闭环` + 驳回重处理，由 service 强制流转。
- **安全**：密码 BCrypt、JWT 鉴权、ORM 参数化防注入、文件上传校验、操作日志。

### 4.2 AI 部署重心
- **模型接入**：DeepSeek 主 + agnes-2.5-flash 降级（qwen3.8max 为视觉子模型），统一 OpenAI 兼容 SDK，超时自动切换。
- **RAG 管线**：结构感知分块 → 本地 bge-large-zh 嵌入 → 混合检索(RRF) → 本地 bge-reranker-base 重排 → 父块注入。
- **服务化**：gunicorn + uvicorn workers 横向提并发；embedding 缓存(Redis)；接口限流保障 ≥50 QPS。
- **可观测**：记录提问/回答/引用(A06)与点赞踩(A07)，形成反馈闭环。

### 4.3 部署架构（P4 负责）
```
Nginx(443) → frontend(静态) + backend(FastAPI:8000)
backend → MySQL / Redis / Chroma(本地卷) / 文件卷(uploads/ppt)
docker-compose 一键编排五服务
```

## 5. vibe coding 使用边界

| 场景 | 方式 | 责任人 | 边界 |
|------|------|--------|------|
| 前端页面 | AI 生成 Vue3 组件壳 + 手动对接 API | P1/P4 抽空发起 | 不排主线，仅最小可用 |
| 测试用例 | AI 辅助生成 pytest 骨架 | P4 统筹 | 需人工 review 后入库 |
| 文档/注释 | AI 草稿 + 人工校正 | 全员 | 不替代技术决策 |

> **原则**：vibe coding 用于"生成快、校验轻"的部分；后端业务正确性、RAG 质量、部署稳定性仍由四人人工把控。
