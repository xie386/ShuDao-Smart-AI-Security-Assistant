# 知识库批量采集说明（D6：90 余份 → 1000+ 份）

> 项目知识库权威性要求 ≥1000 份文档。本文档说明四个采集脚本的来源、用法、
> 治理配合方式与实测结果。**当前知识库有效文档：1070+ 份**（治理后 .md 计数）。

---

## 一、为什么新写脚本（与 D3 `fetch_kb.py` 的分工）

| 脚本 | 驱动方式 | 用途 | 产出规模 |
|---|---|---|---|
| `fetch_kb.py`（D3，保留不动） | **清单驱动**：人工维护 `kb_manifest.jsonl` 精选权威源 | 国务院/交通运输部/应急管理部等**权威原件**，逐条人工核定 | ~90 份 |
| `crawl_*.py`（D6，本次新增） | **列表页驱动**：自动翻页发现详情页 URL | 批量扩容到 1000+，覆盖四类语料 | 1000+ 份 |

两者互补：D3 的 92 条是「答辩要点」级权威文件（安全生产法、判定标准、国家预案），
D6 的批量语料提供**检索广度**（同类事故多案例、同主题多规程），
让 RAG 混合检索有足够候选池。

## 二、四个脚本与数据源

所有脚本位于 `backend/scripts/`，共用公共库 `kb_crawl_common.py`。

| 脚本 | 目标目录 | 数据源 | 栏目数 | 本次实测新增 |
|---|---|---|---|---|
| `crawl_laws.py` | `knowledge_src/laws/` | 安全管理网 **Laws 频道**（法律/法规/规章/通知/意见全文） | 6 | 236 |
| `crawl_procedures.py` | `knowledge_src/procedures/` | 安全管理网 **Manage 频道**（规章制度/隐患排查/安全检查/风险管控/分行业管理） | 19 | 216 |
| `crawl_plans.py` | `knowledge_src/plans/` | 安全管理网 **Emergency 频道** + **应急管理部**预案栏目 | 8 | 168 |
| `crawl_cases.py` | `knowledge_src/cases/` | 安全管理网 **Case 频道**（坍塌/高坠/起重/物击/机械/触电/车辆等 19 类）+ **应急管理部**事故调查报告 | 21 | 450 |

### ⚠️ 选源踩坑（重要，勿再改回）

`crawl_laws.py` 最初用安全管理网 **Standard 频道**（GB/AQ/JTG 技术标准），
实测 **254/315 份是「附件下载页」**——网页正文只有标题 + 一个 .doc/.pdf 下载链接，
治理后 md 仅十几个字，入库纯噪声。**改用 Laws 频道后有效率 ~84%**
（法规类页面把条文全文直接排在正文容器里）。

## 三、用法

```bash
# 在 backend/ 目录下，使用全局 Python（注意清空 PYTHONPATH）
cd backend

# 1) 先看会抓到什么（不下载）
PYTHONPATH= C:\python\python.exe scripts/crawl_cases.py --dry-run --quota 20

# 2) 正式采集（四类可分别跑，互不干扰）
PYTHONPATH= C:\python\python.exe scripts/crawl_cases.py      --quota 420
PYTHONPATH= C:\python\python.exe scripts/crawl_laws.py       --quota 260
PYTHONPATH= C:\python\python.exe scripts/crawl_procedures.py --quota 320
PYTHONPATH= C:\python\python.exe scripts/crawl_plans.py      --quota 270

# 3) 治理：HTML → md（四类全量）
PYTHONPATH= C:\python\python.exe scripts/govern_html.py

# 4) 清理空壳文档（附件下载页等无正文页面）
PYTHONPATH= C:\python\python.exe scripts/clean_empty_kb.py --min-chars 400

# 5) 质量抽检（字数分布 / 主题覆盖度）
PYTHONPATH= C:\python\python.exe scripts/kb_sample_check.py
```

### 命令行参数（四个脚本通用）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--quota N` | 各脚本不同 | 本次目标**新增**份数（已存在的跳过，不计入） |
| `--per-column N` | 0 | 每栏目上限；0 = 按 quota 在各栏目间均分（+20% 余量） |
| `--max-pages N` | 30 | 每栏目最多翻几页（safehoo 约 50 条/页） |
| `--delay 秒` | 0.3 | 请求间隔（礼貌抓取，勿调太小） |
| `--dry-run` | 关 | 只发现不下载 |

## 四、脚本能力（`kb_crawl_common.py`）

1. **列表页翻页发现**：栏目根为第 1 页，后续 `List_<N>.shtml`；
   遇 404 / 空页 / 达配额自动停止；只保留与栏目同路径的详情页（滤掉推荐位跨栏目链接）。
2. **详情页分页合并** ⭐：safehoo 长报告正文分页（`<id>_2.shtml`、`_3.shtml`…），
   自动跟随并把各页 HTML 拼接成一个文件，**否则正文被截断**
   （实测某坍塌事故报告：不合并 2065 字，合并后 10520 字）。
3. **断点续传**：目标文件已存在 / manifest 已有该 source_id → 跳过，可反复重跑。
4. **稳定 source_id**：`<前缀>-<栏目>-<年月>-<文章ID>`，如 `shd-case-collapse-202608-5813940`。
5. **manifest 追加**：与 D3 记录同构，治理脚本回填 title/字数，`collect_kb.py` 入库可溯源。
6. **礼貌抓取**：串行 + 请求间隔，失败重试 2 次；本次实测**四类零失败**。
7. **直连不走代理**：`trust_env=False`（本机代理转发部分站点 502，与 curl `--noproxy` 同理）。

## 五、治理脚本的配套改动（`govern_html.py`）

为支撑新数据源，治理脚本做了 4 处增强，**旧政务站文档零回归**
（实测国家防汛抗旱应急预案 26223 字、国家地震应急预案 13306 字与 D3 记录一致）：

| # | 改动 | 原因 |
|---|---|---|
| 1 | 新增正文容器 `id=pagecontent` / `class=con_zw` | safehoo 正文容器，命中后直接跳过页头导航区 |
| 2 | `pick_containers()` **多容器合并** | 分页合并后的文件有**多个** `pagecontent`，只取第一个会丢掉后续分页正文 |
| 3 | `extract_preview_md()` **textarea 全文预览兜底** ⭐ | 「文档下载页」正文放在 `<div class="con_pl"><textarea>` 里；正文 <500 字时从这里取回（实测救回 4045 字完整规程） |
| 4 | 噪声规则升级：站点噪声词 + 导航菜单项精确匹配 + 列表项形态正则（日期前缀/点击数前缀/省略号截断标题） | 容器未命中走全页兜底时会带入侧栏导航与「推荐/热门」列表 |

另新增 `clean_empty_kb.py`：删除治理后正文过短（默认 <400 字）的 md + htm，
并同步清理 `kb_manifest.jsonl`——这类「附件下载页」入库只会污染检索。

## 七、后续：重建向量库

采集治理完成后，知识库文本已变（新增 ~970 份），**必须清空 Chroma 集合再全量入库**
（稳定 ID 基于内容，治理后文本变化会留下旧块残留）：

```bash
# 1) 清空集合后重新入库（父子块 + parent_text）
PYTHONPATH= C:\python\python.exe scripts/collect_kb.py

# 2) golden QA 评估（注意加 --no-rewrite，否则 50 题超时）
PYTHONPATH= C:\python\python.exe scripts/eval_qa.py --topk 10 --no-rewrite
```

⚠️ 入库耗时预估：1070 份 / 约 550 万字，bge-large-zh (cuda) 嵌入约需 20-40 分钟，
建议手动在终端执行并观察进度。入库后 Recall 指标需重测——候选池扩大约 11 倍，
`DENSE_K/SPARSE_K/FUSE_TOPK=30` 可能需要重新调优。
