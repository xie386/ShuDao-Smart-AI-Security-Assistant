# 文件存放规则（本项目适配版·2026-10-23 立）

> **为什么有这份文件**：这些规则只活在对话与记忆里时会被稀释。规则以**仓库内的文档**为准；**新增文件/目录前先读本文件**。
> **与《版本文档规范（本项目适配版）》的分工**：那份管「同一版本内文档怎么编排、谁先谁后、谁是权威」；本份管「**文件放哪**」。两者不重叠。
> **适配说明**：按蜀道项目（`team/` 下 backend + front + database + deploy 四块）改写自 deep_search_pro 同名规范；上游的 `agent/` `api/` `tools/` `user_data/` 等目录在本项目不存在，不照搬。

---

## 〇、两条硬规矩

1. **前端文件一律放 `front/`**（当前唯一前端家：`front/safety/index.html` 单文件 SPA；`front/demo/` 为演示页）。后端只做静态托管，不在后端目录里写前端代码。
2. **新建子文件夹必须先经用户同意**；新增文件放哪，先查 §三 判据。

---

## 一、顶层：项目根只放「入口 + 配置 + 声明」

| 该放 | 说明 |
|---|---|
| `README.md` | 项目简介 + **阅读指南**（按难度递进的逐文件「看什么 / 思考题」）——这是根 README 的核心章节 |
| `.gitignore` / `.dockerignore` | 忽略与镜像排除配置 |
| `backend/ front/ database/ deploy/` | 四个功能块（见 §二） |
| `RAG_test.txt` | RAG 冒烟测试样本（v1.0 遗留，保留） |

**不放**：临时脚本、调试产物、预览/探针输出、临时提取文件。判据：`*.tmp`、`_chk.js`、`_resp.json`、`nul`、`*.log` 一律不许留在仓库树里（用完即删）；确需留存放 `backend/tests/` 下并加忽略项。

> **原则**：`docs/` 是纯文档信息，**不应被项目运行依赖**。前端或后端真正要用的东西（截图、模板、数据）放在 `front/`、`backend/knowledge_src/` 等处另存；`docs/` 里那份只作文档素材，删了不影响运行。

## 二、每个目录的职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `backend/src/core/` | 基础设施：`config`（pydantic-settings 读 .env）/ `db`（SQLAlchemy 引擎，不建表）/ `redis_client` / `security`（bcrypt + JWT） | 业务逻辑 |
| `backend/src/ai/` | **AI 层**：`llm_client`（ChatOpenAI + 降级）/ `embeddings` / `reranker` / `knowledge`（增量入库）/ `rag`（混合检索）/ `prompts`（YAML 加载）/ `vision` / `exam_agent` / `knowledge_review_agent` / `ppt_baidu` / `ppt_local` | 业务状态机 |

| `backend/src/services/` | 业务层：状态机 / 权限再校验 / 通知 / 时间线 / 清洗治理 | HTTP 细节 |
| `backend/src/schemas/` | Pydantic 契约。**改接口先改 schema 再改 router** | — |
| `backend/src/utils/` | 通用小工具：`files`（上传校验）/ `boxes`（bbox 画框） | 挂给 agent 的工具 |
| `backend/scripts/` | **数据与运维脚本**（非测试）：采集 6 / 治理 3 / 入库 1 / 验证 11 / 评测 2 / 工具 1 | 测试 |
| `backend/tests/` | pytest 测试，扁平命名 `test_<模块>.py`（见 §四） | 产物 |
| `backend/prompt/prompts.yml` | **全部提示词**（主问答 / 视觉 / PPT 大纲 / 出卷 / 知识审核） | 长 prompt 硬编码进代码 |
| `backend/knowledge_src/` | 采集后的知识源（四类目录）+ `ppt_model/`（用户上传模板） | **不入库**（见 §五） |
| `backend/uploads/` | 用户上传与导出产物：隐患图片 / 头像 / `kb_contrib/`（贡献文件）/ `exam/`（历史试卷导出） | **不入库** |
| `backend/ppt_files/` | PPT 生成产物 | **不入库**（§五新增忽略项） |
| `backend/exam_files/` | 试卷导出产物（v2.0 起从 `uploads/exam/` 迁出，不再静态托管） | **不入库**（§五新增忽略项） |
| `backend/chroma/` | 向量库（当前 7.2GB，`scripts/collect_kb.py` 可重建） | **不入库** |
| `front/safety/` | 前端单页应用（`index.html` 一个文件含全部 CSS/JS，hash 路由） | 后端代码 |
| `front/demo/` | 演示页（D3 vibe 对接用） | — |
| `database/schema.sql` | **表结构唯一权威**（10 张表）。代码严禁 `create_all`；改表后必跑 `scripts/db_verify.py` | 模型文件 |
| `deploy/` | Docker Compose + nginx + 后端 Dockerfile（**尚未实测跑通**，P4 延后） | — |
| `backend/docs/` | 文档：`v1.0/`（归档，不维护）+ `v2.0/`（四类编排）+ 两份宪法 + `README.md`（索引） | 被运行依赖的内容 |

## 三、判据速查（新文件放哪）

```text
是前端相关吗？                → front/（唯一家）
是 AI 能力（模型/检索/入库/子智能体）吗？→ backend/src/ai/
是业务规则/状态机/编排吗？     → backend/src/services/
是接口暴露吗？                → backend/src/routers/（并先改 schemas/）
是表结构吗？                  → database/schema.sql（+ src/models/ 对齐）
是数据生产/运维脚本吗？        → backend/scripts/
是测试吗？                    → backend/tests/test_<模块>.py
是提示词吗？                  → backend/prompt/prompts.yml
是用户上传/生成产物吗？        → backend/uploads/ 或 ppt_files/、exam_files/（均不入库）
是知识源吗？                  → backend/knowledge_src/
是文档/方案/记录吗？          → backend/docs/<版本>/（v2.0 起按四类）
是版本级裁定/方案/调研吗？     → backend/docs/v2.0/{Verdict,research}/NN-*.md
是版本冷启动入口吗？          → backend/docs/v2.0/交接文档.md（不分进四类）
是改用户数据前的备份吗？      → backend/docs/v2.0/backups/（版本提交后即删，不入库）
是文档体系索引吗？            → backend/docs/README.md
是部署编排吗？                → deploy/
```

## 四、`tests/` 口径

- 结构：**扁平**，`backend/tests/test_<模块>.py`（现有 10 个文件即此结构，不做 `unit/` `live/` 分类重构）。
- 两类测试并存：**依赖真实 MySQL 的集成测试**（auth / users / hazards / uploads / stats_notifications）与**纯函数单测**（exam / knowledge_contrib / user_profile / chat 用 monkeypatch）。
- **测试账号与数据口径**：
  - 探针/单测**不得向真实库建号**、**不得向实时目录写文件**；要落盘就落 `tempfile` 或 `tmp_path`；
  - 必须用真实账号验证时，**只发只读请求**（GET）；需要写时用 `t_` + 用途 + 时间戳命名的临时账号，跑完自清；
  - 非 `t_` 前缀的账号一律视为真实账号，只读对待；
  - 现有真实账号：`admin`（id 17，管理员）、`尼古喵喵`（id 608，普通员工）等；密码以 bcrypt 存储，**不可反查**。
- **已知问题**：全量 `pytest tests/` 在第 7 个用例后挂起（超 300s 未收敛，原因未定位）。在大点回归中**只跑相关子集**，把它当独立事项另立，不混入无关改动。

## 六、巡检（每个大点收官时跑一遍）

| # | 检查项 | 查到怎么办 |
|---|---|---|
| 1 | 仓库树里有无 `*.tmp` / `_chk.js` / 裸产物 | 删；需留存放 `backend/tests/` 并加忽略 |
| 2 | 有无遗留临时账号 / 孤儿测试数据（循环注册产生的 `rep_*` / `tester_*` 等） | 记录在案；清理需用户同意（属数据删除） |
| 3 | `docs/v2.0/backups/` 是否「应删未删」 | 该版本已提交 → 删 |
| 4 | 新增目录有没有登记进 §二 与 §五 | 未登记 → 补登记（或先问用户） |
| 5 | 有无本机化绝对路径混进代码默认值 | 改为 `.env` 配置项或明确提示（本地模型路径属例外，见 `config.py`） |
| 6 | `ppt_files/` `exam_files/` `uploads/` 体积是否异常增长 | 与用户确认后清理 |

## 七、与上游规范的差异（不照搬的部分）

| 上游 | 本项目 | 原因 |
|---|---|---|
| `agent/` `api/` `cli/` `tools/` `utils/` `rag_knowledge/` `user_data/` `data/` 分治 | `backend/src/{core,ai,models,routers,services,schemas,utils}` + `front/` + `database/` + `deploy/` | 本项目是 FastAPI 单体后端 + 单文件前端 |
| `tests/` 五类分治（`unit/harness/testclient/live/debug`） | 扁平 `test_*.py` | 现有结构与体量不值得重构 |
| 用户数据按账号归口 `user_data/{账号}/` | 无多账号数据目录概念：业务数据在 MySQL，文件在 `uploads/` | 本项目账号数据全在库里 |
| 常青设计图放项目根 | 本项目暂无设计图，出现时再定 | — |
