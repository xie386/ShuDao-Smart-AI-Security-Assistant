## 二、实现要点（与方案的对应）

1. **门禁位置**：`event_stream()` 第一行 `intent.detect()`，早于 `_prepare()`（预处理 + 检索）——裁定 1/3。
2. **闲聊分支**：`mode="chat"`、`meta.sources=0`、`context_chars=0`；不调 `query_preprocess` / `retrieve_queries` / `chat_agent`；`refs` 只写 `{"intent": {...}}`；**不写** `conv_rag_cache`（不 `put_blocks`、不 `touch`）。
3. **判定输入**：`last_round_hint()` 在 `save_message` **之前**取，保证拿到的是上一轮；超 `CHAT_INTENT_MAX_HISTORY_CHARS` 时按字符截断（问题在前、回答在后，优先保留问题）。
4. **失败回退**：`detect()` 永不抛异常 → `knowledge` + `degraded{kind:"intent", why}`；三种情况都覆盖（超时/异常/输出不可解析）。
5. **检索降级**：`retrieve_queries` 三处调用统一走 `_safe_retrieve()`；另在 `event_stream()` 外包一层，`_prepare()` 整体崩也降级。降级时 `context=RETRIEVAL_DEGRADED_NOTE`（明确"未检索企业知识库、不含出处"），`sources=[]`、assistant `refs=None`。
6. **审计**：`refs.intent` 与 `refs.preprocessed` 并列；`build_rounds()` 对"只有 intent 没有 preprocessed"的闲聊轮照常成轮。
7. **回滚**：`CHAT_INTENT_ENABLED=false` → `detect()` 直接返回 knowledge 且**不调模型**（单测锁住）。

## 四、偏差与问题（实现期）

1. **判定客户端的超时不能复用 `llm_client.chat`**：`ChatOpenAI.model_copy(request_timeout=...)` 实测**不生效**（0.001s 超时下请求照常成功）。改为 `intent.py` 自建一个 `ChatOpenAI`（构造级 `timeout=CHAT_INTENT_TIMEOUT`、`max_retries=0`）。代价：多一条连接池，但判定与主链路的超时策略互不影响。
2. **降级范围比方案宽**：方案只写"检索段包 try/except"，实现里额外在 `event_stream()` 外层兜住 `_prepare()` 整体异常（预处理/判定/向量库初始化崩了同样不 500）。方向一致、覆盖更全。
3. **`tests/conftest.py` 成了必需件**：门禁让每个 `/api/chat` 用例都会打一次真模型。新增 autouse 桩（默认返回 knowledge），否则单测会变慢/变贵/看网络脸色。这是对既有测试基础设施的改动，需要知会。
4. **`tests/test_chat.py` 原有 2 个用例本来就不稳**：它依赖"Agent 调用失败 → 回落假流"，一旦网络正常 Agent 真答了，断言假流文本就挂（本次跑到过）。顺带加了确定性夹具，不改断言口径。
5. **闲聊答案的能力描述偏保守**：问"能上传什么格式的模板"时，模型答"取决于系统后台上传页的配置，我不能替你确认具体清单"。没编造，但用户体验一般；根治要把 capabilities（PPT 模板扩展名、知识上传类型）拼进 `chat_assistant`，属下一轮小改。

## 六、遗留

1. **闲聊能力清单**（见 §四.5）：把 `capabilities()` 一类事实拼进 `chat_assistant`，避免"我不能替你确认"。
2. **判定成本**：每轮固定多一次模型调用（~0.5~0.9s）。若后续发现高频闲聊场景可以加"连续闲聊短路"，但那会回到规则/状态机，需重新裁定。
3. **`AGENT_ENABLED` 与闲聊**：闲聊直答**不走** Agent（按裁定 3），所以 Agent 的补检能力在闲聊路径不可用 —— 属设计选择，不是缺陷。
4. **全量测评集**仍未跑（01 裁定 1 延后），本大点只跑了定点样本。

## 七、回滚

- 单开关：`.env` 设 `CHAT_INTENT_ENABLED=false` → 全量按知识问答处理（等于 01 收官行为），重启即生效。
- 提示词可单独回退：`chat_intent` / `chat_assistant` 两个场景互不影响。
- 检索降级**无开关**（只影响异常路径），如需完全回到旧行为需回滚 `chat.py` 的 `_safe_retrieve` 三处调用。
