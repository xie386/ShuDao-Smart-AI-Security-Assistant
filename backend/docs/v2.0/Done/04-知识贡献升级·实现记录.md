## 三、偏差与问题（实现期）

1. **MinerU 4.x 的 `mineru parse` 需要本地服务**（`mineru server start`）→ 改为优先调用 **`mineru-kit`**（同包、免服务），代码自动选择（`_resolve_exe`）；配置默认值改 `KB_MINERU_CMD=mineru-kit`。
2. **PDF 默认只解析前 10 页** → 显式 `--pages all`；39 页实测 89s，把 `KB_MINERU_TIMEOUT` 提到 **600s**。
3. **MinerU 偶发结果异常短**（字体未嵌入的 PDF 只吐标题）→ 增加"与兜底结果比较，短于一半即回退"的护栏。
4. **文件名用的是上传原文件名**（E2E 里是 `e2e_9fb076.md`），与草案"约等于原文件名"一致；标题是否重复由审核端的双重查重把关，不做自动改名。
5. **`clean_empty_kb.py`（<300 字删除）没有改**：1000 字门槛已让贡献永远不会低于该阈值，属"用规则解决"而非改脚本。
6. **D 盘两次掉线打断验证**：`WinError 433`（读 `knowledge_src/procedures`）与 Chroma `disk I/O error`；盘恢复后重跑通过，Chroma 未损坏（17,797 块）。这是环境问题，不是代码问题。
7. **探针账号残留**：验证过程中注册过 `e2e_kc_*` / `intent_probe_*` / `ui_probe_*` 等一次性账号（部分带会话）；贡献与块已清理，账号未删（删账号要级联删会话，属数据操作，留给你决定）。

（#11 是补丁前样例，已删除；**#13 保留为演示记录**，可在审核界面驳回。）

### 本轮补齐的四处（原实现漏项）

1. **触发信号不全**：原实现只看「检索降级 / 0 命中」，用户那种「检索到资料但答不了」不触发 → 增加 `answer_declares_gap()`（答案自述「资料中没有/无法确认/未覆盖」）+ 工具侧 `gap_report`。
2. **缺来源小字**：方案要求 md 第 2 行标 `Agent 贡献（模型）· 来源 URL` → 已加 `_with_provenance()`（不影响 `_first_title()`，首行仍是 `# 标题`）。
3. **`agent_runs` 是「结束补记」而不是「建任务」**：改为开始时建 `running` 行、结束时回填同一行。
4. 额外护栏：总结正文 <1000 字 → **不提交**，`agent_runs.status=insufficient` 并回写案例（避免产生必然被审核拒掉的待审单）。

## 三-c、Agent 贡献内容质量整改（2026-10-26，用户第二次反馈）

### 问题

用户附两份 Agent 贡献原件（`贡献15_原件.md`、`贡献13_原件md`）：通篇是「缺什么 / 来源什么 / 为什么要补 / 请人工补录」的
**需求调研文档**，没有一条可执行知识。示例：正文 2,772 字里 12 张"待补录"表格、0 条可引用条款。

### 根因（两层，缺一不可）

| 层 | 现象 | 取证 |
|---|---|---|
| 搜索源 | Bing 中文查询返回无关页 | 探针：`水下作业 潜水 装备 要求` 返回「股票水下什么意思 / 小红书水下笔记」，抓到的落地页是 `dxzhgl.miit.gov.cn` 企业年报、`beian.mps.gov.cn` 备案首页 |
| 提示词 | `agent_summarize` 要求「正文 ≥1000 字，不足时说明公开资料有限」 | 材料无关 → 模型为凑字数写成"缺口登记 + 相关性判定 + 维护步骤" |

### 整改（5 项）

1. **搜索源配置化**：`KB_SCOUT_ENGINES`（`名称|URL模板|结果选择器`，`;` 分隔）。默认 `360 → sogou → cn.bing`；
   百度对无头 Chromium 会弹 `wappass` 验证码（实测），故不入列。候选链接按各引擎结果选择器抽取，不再抓整站导航。
2. **来源白名单化**：搜索页、文库聚合（`wenku.*`、`renrendoc`、`book118`…）一律不当来源；跳转链接跟随落地后再判。
3. **相关性 + 条款级证据**：缺口关键词命中 ≥2（或 1 命中 + 长文 + 有条款结构）；非权威站点必须出现 `第X条` / `GB(T) xxxx` / `x号文` 才收。
4. **提示词改为"只抄要求"**：结构固定，每条后必须 `[来源: URL]`，禁止「待补录/缺口说明/维护步骤」；材料不可用只输出一行 `INSUFFICIENT`。
5. **知识含量闸门 + 补采**：`_knowledge_quality()` 要求 ≥1000 字、≥3 处引用、≥5 条目、无叙事关键词；
   材料偏少时放宽检索词再采一轮重试；仍不过 → `agent_runs.status=insufficient`，**不产生待审单**，案例写回 `cases.md`。

### 实测对比

| 轮次 | 贡献 | 结果 |
|---|---|---|
| 整改前（用户截图） | #13 / #15 | 「缺口说明」2.7k 字、0 条款、12 张"待补录"表 → 用户驳回 |
| 整改后 #19 | 水下作业 | 2,152 字 / 18 处引用 / 来源 `aoc.ouc.edu.cn`（中国海洋大学载人潜水器作业要求） |
| 整改后 #20 | 地下矿山爆破 | 2,163 字 / 12 处引用 / 来源 `mem.gov.cn` + `rongjiang.gov.cn`：自救器 ≥30min、备用量 10%、每班组 1 台便携式气体检测仪 |

同一批问题里，材料确实不够的主题（如只搜到题库/文库页）现在会**明确不提交**，`agent_runs` 记 `insufficient` 并写明原因。
