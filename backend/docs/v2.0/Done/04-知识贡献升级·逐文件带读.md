# 04 知识贡献升级 + Agent 渠道 · 逐文件带读

> 给接手的人：**每处为什么这么写、改错会怎样**。按"一次审核通过"和"一次 Agent 采集"两条运行时序排。
> 配套：`04-知识贡献升级·实现记录.md`（做了什么 + 实测）、`../../Verdict/04-知识贡献升级.md`（裁定）、`research/04-知识贡献升级.md`（现状与草案评估）。

## 1. 两条主线，一句话

- **人工贡献**：上传 → 待审 → 审核通过时**转 md → 清洗(≥1000 字) → 查重 → 写 `knowledge_src/四类` → 入库** → 首页政策文件/引用立刻可用。
- **Agent 贡献**：回答后发现"资料缺" → 后台 Playwright 按方法论搜集 → LLM 总结成 md → 以 `knowledge_scout` 身份提交 → **同样人审**。

## 2. `src/services/kb_convert.py`：格式转换的"唯一入口"

| 位置 | 要点 |
|---|---|
| `to_markdown()` | 按扩展名分发；返回 `{md, converted_by, warnings, title}`；`converted_by ∈ direct/builtin/mineru/fallback` |
| `_normalize()` | 去 front-matter、**删图片引用**、保证首行是 `# 标题`、压缩空行。首行决定 `kb/list` 的标题显示 |
| `_from_html()` | `markdownify` + 预先 decompose `script/style/title/nav/footer`；实测保留 h1/表格/列表 |
| `_from_docx()` | 按 `document.element.body` **交错**遍历 `p`/`tbl`：Heading 样式→`#`、表格→md 表格。这是兜底路径，实测 0.024s |
| `_from_pdf()` | `get_text("dict")` 取字号分布定层级（峰值=正文，>1.6×→`##`，>1.18×→`###`）；`find_tables()` 还原表格；`_repeated_edge_lines()` 去页眉页脚 |
| `_resolve_exe()` | 配置为 `mineru` 时**自动改用 `mineru-kit`**（`mineru` 需要本地服务，kit 不用） |
| `_build_mineru_args()` | 自适应两代 CLI：v4 `parse <in> -o <out> --tier … --pages all --wait …`；老版 `-p <in> -o <out> -m auto`；`KB_MINERU_ARGS` 可完全接管 |
| `_from_mineru()` | 临时输出目录、超时、非零退出、无 md → 返回 None 由上层兜底；成功则取最大 md |
| 回退护栏 | MinerU 结果 **<200 字**且兜底结果 >2 倍 → 用兜底并记 warning（字体未嵌入的 PDF 会踩） |

**改错会怎样**：把 `--pages all` 去掉 → 60 页报告只进前 10 页且不报错；`_normalize` 不删图片引用 → 分块里全是 `![](images/xxx.jpg)` 噪声。

## 3. `src/services/contrib_store.py`：落盘与回滚（裁定 1/2/6）

```
normalize_stem(原始文件名)   → 去扩展名/非法字符，截 60 字
find_conflict(db, type, 标题, stem)
    ├ 目标文件已存在      → ConflictError("file")
    ├ 目录内标题重复      → ConflictError("title")
    └ DB 已入库标题重复   → ConflictError("title")
写 .tmp_{uuid}.md → upsert_file(doc=stem, source=相对路径, meta{contrib_id, origin})
    → 成功: tmp.replace(最终名) → 更新 DB 字段（md_path/chunk_count/convert_by/source_kind/...）
    → 失败: 删 tmp + remove_chunks(stem)（回滚已写入的块）
```

- **为什么先临时名**：rename 同目录原子；入库失败时绝不会留"文件在目录里但库里没有"。
- **为什么不用 `contrib_{id}` 前缀**：草案要求"前端显示最终 md 文件名"，且 `doc` 直接决定引用标签与 `kb/doc` 可打开性。
- **`remove_chunks()`**：`collection.delete(where={"doc": stem})`，只删该文档命名空间，不影响官方源。

## 4. `src/ai/knowledge.py`：`upsert_file()`

与 `build_from_dir` 共用 `SPLITTERS` 与 metadata 口径，唯一差别是：
- `doc` 取传入的 `stem`（默认文件名）；
- `source` 固定成 `knowledge_src/{type}/{file}`（**必须相对路径**，绝对路径会被 `kb/doc` 的前缀校验挡下）；
- `extra_meta` 合并进每个子块（`contrib_id` / `origin` / `source_agent_id`）。
另外把"跳过 <2000 字节"改成读配置 `KB_BUILD_MIN_BYTES`。

## 5. `src/services/knowledge_contrib_service.py`：审核链路

`review(approved=True)` 的顺序**不能换**：

1. 取原件（`UPLOAD_DIR/contrib.file_path`），缺文件直接 422；
2. `kb_convert.to_markdown()`（MinerU 优先）；
3. `kb_govern.clean_text()` → `quality_check(min_chars=KB_CONTRIB_MIN_CHARS)`；
4. `contrib_store.store_contribution()`（内部再查重——**不能挪到转换之前**，因为标题要看 md 首行）；
5. 更新状态/审核人/备注 + 时间线（`actor_kind`）；
6. 通知贡献者。

`submit()` 只多了两件事：`.html/.htm` 解析分支（bs4 取文本存 `content` 供预览）、记录 `origin_filename` / `source_kind='user'`。

## 6. `src/ai/agent_scout.py`：Agent 网搜

| 段落 | 关键点 |
|---|---|
| `url_allowed()` | **硬边界**：只 http/https；禁 localhost/本机/内网/保留/多播；`KB_FETCH_DENY_HOSTS` 追加；DNS 解析失败即拒（防绕解析） |
| `_host_quality()` | **软策略**：百科/文库/问答/门户 → -1（不采）；`.gov.cn/.org.cn/.edu.cn` → 2（排前） |
| `should_scout()` | 闲聊不出手；`retrieval_degraded` 或 `sources==0` 才出手 |
| `kick_off()` | 后台线程 + 进程内幂等键（conv+问题哈希），失败只记日志 |
| `_plan_queries()` | LLM 依据方法论产出 1–2 条检索词（`agent_plan`），失败退回原问题 |
| `_collect()` | 打开 `KB_SCOUT_SEARCH_URL`（默认 Bing）→ 抽链接 → 质量排序 → 逐个开页面取 `inner_text`；限额：站点/页数/字节/时长 |
| `_summarize()` | `agent_summarize` 提示词：≥1000 字、带 `## 来源`、不许编条款 |
| `run()` | 汇总 → `submit_agent()` → 写 `agent_runs`（status=submitted/failed）→ 成功时回写 `cases.md` 一行 |

**改错会怎样**：把 `url_allowed` 的 IP 校验去掉 → SSRF（能打内网与本机服务）；把触发条件放宽成"每轮" → 每轮都起采集，成本与外网压力失控。

## 7. `src/services/agent_contrib_service.py` / `src/models/agent.py`

- `agent_clients`：身份表（name / api_key_hash / model / owner_user_id / scopes / enabled）。
- `authenticate()`：`sha256(raw_key)` 与库中比对，`enabled=1` 才放行。
- `submit_agent()`：md 落 `uploads/kb_contrib/agent/{uuid}.md`；建贡献行（`source_kind=agent`、`origin_urls` JSON）；时间线 `actor_kind=agent`、`operator_id=None`；通知全部 admin。
- `contributor_id` 非空约束 → 挂到第一个 admin（`_fallback_contributor`），**真实来源由 `source_agent_id` + timeline 表达**。

## 8. `src/services/agent_docs.py` + `src/routers/kb_agent_docs.py`

- 目录：`PROJECT_ROOT/Methodology`（`KB_AGENT_DOCS_DIR` 可改）；
- `read()` 缺失时回退 `.example` 并标 `from_example=True`（前端会提示"尚未创建"）；
- `write()` 先 `copy2` 成 `.bak` 再写；
- `version()` = 内容 sha1 前 8 位（写进 `agent_runs.methodology_version`，可追溯"当时用的是哪版方法论"）；
- `regenerate()`：读 `recent_cases(20000)` + 现有方法论尾 6000 字 → `methodology_writer` → 至少 200 字才覆盖，否则报错不写。

## 11. 最容易改错的五处

1. **`source` 写成绝对路径** → `kb/doc` 打不开（前缀校验只认 `knowledge_src/`）。
2. **首行不是 `# 标题`**（例如放了 front-matter）→ 首页政策文件列表标题变 `---`。
3. **先查重后转换** → 标题来自 md 首行，转换前的"标题"其实是用户输入，会漏判。
4. **`tmp.replace()` 放在入库之前** → 入库失败留下"有文件没块"的脏数据。
5. **采集触发放进 SSE 生成器** → 客户端断开即取消、并且直接把回答时延拖长。
