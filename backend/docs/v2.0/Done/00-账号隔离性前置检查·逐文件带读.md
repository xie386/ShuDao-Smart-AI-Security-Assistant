## 1. `backend/src/services/ppt_service.py`（+36/−2）

**在链路里的位置**：PPT 生成（P03）与下载（P07）的业务层，产物文件名与访问控制都在这里。

| 行 | 内容 | 检查要点 |
|---|---|---|
| `:259` | `_artifact_dest(task)` | 命名 = `u{task.user_id}_t{task.id}_{主题}.pptx`。为什么用 `task.user_id` 而不是请求里的 `user_id`？（答案：以库中记录为准，防「用别人的任务 id + 自己的 token」造出错误归属） |
| `:153` | `generate()` 里 `dest = PptService._artifact_dest(task)` | 生成前已 `_get_owned`，所以 `task` 一定是本人的；产物路径在 `task.status = 生成中` 之后才计算，失败不会留半成品命名 |
| `:227` | `download_path()` | 五步校验：归属 → 状态/`file_path` → 只取 basename → 白名单 → 存在性。注意第 3 步顺序：**先 basename 再拼接**，所以 `..` 在这之前就消失了 |
| `:242` | `PPT_FILES_DIR.resolve() not in p.parents` | 白名单用 `parents` 而非 `startswith` 字符串比较（后者会被 `/ppt_files_evil` 骗过） |

**思考题**：同一任务重复点「生成」会发生什么？（答：命中同名 → 覆盖自己的文件，符合预期；若改成带时间戳，磁盘会无限增长）
