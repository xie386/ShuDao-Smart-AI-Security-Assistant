## 一、一句话版

旧版是「每用户一个 Redis list，只读不删」：重启就丢、未读是假的、消息没时间、只能整体清空。
新版 = **Redis 管消息（会自己消失）+ MySQL 管记录（可长期翻阅）**，菜单改名「消息与记录」，页内两个 tab。

| 维度 | 旧 | 新 |
|---|---|---|
| 存储 | Redis list，单条无 TTL | Redis `HASH + ZSET`，条目级 `expire_at`，读时惰性清理 |
| 未读 | `unread = LLEN`（假） | 真已读：进页面标已读，角标递减（但本次仍高亮新消息） |
| 时间 | payload 无时间戳 | 每条带 `created_at`，前端显示相对时间 + 悬浮绝对时间 |
| 生命周期 | 只有「清空全部」 | 闭环删上报/整改/派单；驳回堆积到通过时清空；通过/最终处理/知识贡献留 1 天 |
| 记录 | 无 | 新表 `message_records`：闭环隐患快照 + 知识贡献结果，按角色过滤 |
| 跳转 | 正则从文案抠「贡献 #id」 | 显式 `contrib_id` / `hazard_id` |
| 实时性 | 仅登录刷一次角标 | 30s 轮询，页面隐藏暂停，回页立即刷 |
| 洪泛 | 验收给 109 admin + 47 sfo 各发 2 条 | 验收只发责任人；最终处理给上报人 + admin；闭环删旧消息 |

## 三、消息生命周期（实现后的实际口径）

| 事件 | 收件人 | Redis 保留 | 闭环时 |
|---|---|---|---|
| 上报 | 全部 admin | 不限期 | 删除 |
| 派单 | 责任人 | 不限期 | 删除 |
| 整改反馈 | 全部 admin | 不限期 | 删除 |
| 验收驳回 | 被派单责任人 | 不限期（堆积） | 通过时全删 |
| 验收通过 | 被派单责任人 | 1 天 | — |
| 最终处理 | 上报人 + 全部 admin | 1 天 | — |
| 知识贡献（待审/结果） | admin + 贡献者（Agent 不发） | 1 天 | — |

> 实现顺序：先删（上报/整改/派单 + 堆积驳回）→ 再发（通过 + 最终处理）→ 最后写记录；记录写入在验收事务提交之后，失败只记日志。

## 五、实现期发现并修掉的问题

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | 同一秒内消息顺序乱（`测试 0/2/1`） | ZSET score 用整秒，同分按成员字典序 | score 改**浮点秒** |
| 2 | Redis 挂掉时上报请求卡死数分钟 | 109 个 admin × 每次连接约 2s 超时，逐个重试 | `socket_connect_timeout=1s` + 消息服务 **30s 熔断** |
| 3 | `TYPE_ASSIGN` 未定义（派单 500） | 导入列表漏了一个常量 | 补导入 |
| 4 | 驳回后直接整改被拒（400） | 真实流转是 `已驳回 --派单--> 处理中 --整改--> 待验收` | 探针补"重新派单"步骤；文档记下这条流转 |
| 5 | 进页面后"未读"高亮立刻消失 | 标已读与渲染同步做 | 拆两步：先请求已读（角标立刻减），本次渲染仍按未读高亮 |
| 6 | 消息太慢时收件人为 `None` 会造孤儿键 | 旧集合运算优先级 | `push` 对 `None` 硬拦并记日志 |

## 六、已知限制 / 保留口径

1. **Redis 重启仍会丢当天的短期消息**（`final / accept-pass / kb_contrib`）——"Redis 为主"的固有代价；记录表不受影响。
2. **admin 不再收到「验收结果」**：驳回情况要去隐患详情时间线看（用户拍板的人群）。
3. **记录从上线后开始积累**，190 条历史隐患不回填（用户拍板）。
4. 已读状态存在 Redis 条目里，重启后消息丢了，已读也就无从谈起。
5. 单用户上限 500 条，超出淘汰最旧（避免无界增长）。

## 八、验收建议

1. **Ctrl+F5** 后看左侧菜单是否变成「消息与记录」；角标是未读数；
2. 用管理员：上报一条隐患 → 收到「接收上报」；派单 → 责任人收到「整改任务」；整改 → 管理员收到「整改反馈」；
3. 验收**驳回** → 责任人只收到一条驳回（不限期）；管理员处**没有**最终处理；
4. 重新派单 → 再整改 → 验收**通过** → 管理员的上报/整改/派单消息**消失**，只剩「最终处理」；责任人只剩「验收通过」；
5. 进「消息」tab：未读高亮、时间显示、点进去能跳到隐患/贡献；角标随即减一；
6. 进「记录」tab：能看到刚闭环的隐患（安全员能看全部、员工只看自己上报的），点开有完整时间线与驳回次数；
7. 等 30s 不动页面：角标会自己刷新（页面在后台时不会请求）。
