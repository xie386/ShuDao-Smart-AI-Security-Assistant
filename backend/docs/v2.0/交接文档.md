## 三、纪律

1. **阶段只前进不跳跃**：占位 → 调研 → 定方案 → 实现 → bug 修复 → 记录；**每阶段推进只凭用户口令**，不得以「调研已充分」为由自行补方案或开工。
2. **一份文档只承担一类职责**：规划文档 = 方案；`research/` = 调研信息（多方向、含废案）；`Verdict/` = 一切「选型 / 取舍 / 为何这么定」；`Done/` = 实现过程与逐文件带读。
3. **实现期只读两份**：规划文档对应大点 + `Verdict/`。**不通读 `research/`**（里面混着被否掉的路线，通读会污染判断）；确需核对依据时带着具体问题定点查。
4. **bug 修复两步不许跳**：先脚本自测（单测 / 离线自检），再真机客户端点一遍（浏览器手工验收）。
5. **文档里写数字必须能复跑**：写了「N 个用例通过」就要给出复跑命令，否则等于没写。

## 四、本机环境与已知坑（省得重新踩）

| 项 | 事实 |
|---|---|
| Python | 全局 `C:\python\python.exe` 3.12.4；**所有命令必须加 `PYTHONPATH=` 前缀**（否则 Hermes venv 注入导致依赖错配） |
| MySQL | 127.0.0.1:3306 在跑，库 `shudao_safety`；表结构唯一权威是 `database/schema.sql`（代码不 `create_all`） |
| Redis | 6380；本机由 xieky 后台启动（`redis-server --port 6380 --requirepass 123456`）。**01 起会话缓存依赖它**；不可用时自动走「上下文回顾 + 缺口补检」退化路径，前端状态行会标「Redis 不可用（退化模式）」 |
| 后端 | 未启动；启动 `PYTHONPATH= C:\python\python.exe -m uvicorn src.main:app --port 8000` |
| 启动预热 | 01 起后端启动会起 `rag-warmup` 线程预热检索链路（BM25 语料 + 索引 + embedding + 重排）。日志出现「检索链路预热完成: {...total_s: 34~36}」才算热态；预热中提问会等待（`_await_warmup`），不会重复建索引 |
| BM25 语料缓存 | `backend/bm25_corpus.pkl`（约 17.8MB，`chroma/` 同级，**不入库**）。删除后下次启动重建；知识入库由 `upsert_chunks` 主动失效。切勿再把 `metadatas`（含 `parent_text`）写进这个缓存——会变 2.2GB |
| 日志 | `main.py` 模块级 `logging.basicConfig(INFO)`。看提速链路耗时搜 `问答完成 conv=`，能看到 `preprocess=/judge=/retrieve=/generate=` 分段毫秒数 |
| **别用 `contextvars` 传请求级上下文** | 同步生成器（SSE）在 Starlette 里被 `iterate_in_threadpool` 逐次 `next()`，每次都在线程池的新 context 副本 → `ContextVar.set/reset` 会抛 `different Context`，异常被回落分支吞掉（现象：Agent 一直「回落直连 LLM」）。请求级上下文走 LangChain `config.configurable` + `ensure_config()` |
| pytest | **全量不收敛**：7 个用例通过后挂起超 300s（ISO-6，原因未定位）；本大点回归只跑相关子集（`test_chat.py` / `test_exam.py` / 新增的隔离用例） |
| 探针纪律 | 只读探测不建号、不写实时目录；本次交叉验证用真实账号签发 token 只发 GET |
