# 04 知识贡献升级 + Agent 知识贡献渠道 · 裁定

> 裁定只写结论与依据；方案正文在 `../v2.0规划文档.md` §04，现状与实测证据在 `research/04-知识贡献升级.md`（§1–§9）。
> 依据：用户 2026-10-24 需求原话 + 2026-10-25 草案（《知识贡献链路升级与Agent贡献渠道开发》）+ 2026-10-26 两轮口径确认 + 本项目实测。

## 裁定 1：贡献产物落 `knowledge_src/{doc_type}/`，文件名即最终 md 文件名

| 项 | 内容 |
|---|---|
| **分叉** | ① 维持现状（`doc=contrib_{id}`、`source=user_contrib`，只存 uploads）；② 通过审核后写成 md 落到 `knowledge_src/{四类}/`。 |
| **裁定** | **②**。文件名 = **最终处理好的 md 文件名**（由原文件名归一化而来，约等于原名）；落盘路径 `knowledge_src/{doc_type}/{stem}.md`；`doc=stem`、`source=knowledge_src/{doc_type}/{stem}.md`。 |
| **依据** | 用户 2026-10-26 明确"只要通过审核就放在 knowledge_src 四类子文件夹中""前端列表改成最终处理好的 md 文件名"。技术上 `GET /api/kb/list`、`GET /api/kb/doc`、首页政策文件搜索都只认这条路径 —— 写进去即**前端零改造可见、可搜、引用可点开**（解决 §2 的 1/2/6 三个断点）。 |
| **附加** | 正文第 1 行必须是 `# {标题}`（`kb._first_title()` 依赖它）；第 2 行是来源小字：`> 用户推荐 · 贡献 #12 · 审核通过 2026-10-26`，Agent 则为 `> Agent 贡献（模型名） · 来源 URL：… · 审核通过 …`。**不用 front-matter**（会把列表标题变成 `---`）。 |
| **metadata** | 分块入库时追加 `contrib_id`、`origin`（`user\|agent\|official`）；`doc_type` 沿用分块器的中文标签。 |

## 裁定 2：双重查重，命中即由管理员以「标题重复」驳回；本期不做覆盖/修订

| 项 | 内容 |
|---|---|
| **查重口径** | ① 目标目录同名文件（`{stem}.md` 或 `.txt` 已存在）；② md 首行标题与既有文档标题相同（扫 `knowledge_src` 四类 + DB 内 `已入库` 贡献的 `title`）。任一命中 → 审核界面提示"标题重复"，管理员驳回理由自动带该文案。 |
| **依据** | 用户 2026-10-26："同标题问题在管理员端检测审核，作为反对理由：标题重复"。 |
| **不做** | 覆盖、版本链、下架（用户明确"目前不考虑下架功能开发"）。同标题再次提交只能驳回，改名后再提交。 |

## 裁定 3：贡献正文门槛提到 **1000 字（清洗后有效字数）**

| 项 | 内容 |
|---|---|
| **裁定** | 贡献路径的字数门槛由 `_MIN_HARD=300` 改为 **`KB_CONTRIB_MIN_CHARS=1000`**（作用于 `kb_govern.clean_text()` 之后的字符数，不是上传原始字符数）；`short` 标注区间改为 `1000–2000`。 |
| **依据** | 用户 2026-10-26："贡献至少 1000 字"。用清洗后字数可防"噪声凑数"；同时**顺带消掉两个历史坑**：`build_from_dir` 跳过 <2000 **字节**、"`clean_empty_kb` 删除 <300 字"——1000 汉字 ≈ 3000 字节，均不触发。 |
| **残留风险** | 正文以 ASCII 为主时 1000 字可能不足 2000 字节 → 实现时给 `contrib_` 前缀文件名做**跳过阈值豁免**（见裁定 9 的配置）。 |

## 裁定 4：格式支持与转换链路 —— 内置轻量转换 + **MinerU CLI 处理 docx/pdf**

| 输入 | 处理 |
|---|---|
| `.md/.markdown` | 直通（补首行标题、去掉原 front-matter） |
| `.txt` | 改名 + 补 `# 标题` + 来源小字 |
| `.html/.htm` | `markdownify`（先删 `<script>/<style>/<title>`），再过 `kb_govern` |
| `.docx` | **MinerU CLI**（Office 固定走 Flash 原生解析，不加载模型）→ md；表格由 MinerU 还原 |
| `.pdf` | **MinerU CLI**（`--pages all`，tier 默认 `basic` 以启用表格模型）→ md |
| 兜底 | MinerU 未安装 / 超时 / 失败 → 轻量转换器：docx 用 `python-docx` 按 body 交错遍历段落+表格；pdf 用 `pymupdf` 字号分级 + `page.find_tables()`；结果标 `converted_by=fallback` 并在审核界面提示"表格可能不完整" |

**依据**：用户 2026-10-26 明确"接入 mineru cli 工具，为了解决 pdf 和 docs 中可能的表结构"；实测 MinerU 4.0 支持 DOCX 原生解析、PDF 四档、Windows/CPU 走 ONNX 小模型（research §9.2）。兜底路径来自实测（docx 0.024s 保标题+表格；9/9 PDF 有文本层）。

## 裁定 5：MinerU 以 **独立工具环境 + 子进程** 接入，绝不装进后端解释器

| 项 | 内容 |
|---|---|
| **裁定** | 安装方式 `uv tool install mineru`（独立 venv）；项目通过 `subprocess` 调用 CLI，配置项：`KB_MINERU_ENABLED`、`KB_MINERU_CMD`（默认 `mineru`）、`KB_MINERU_TIMEOUT`（默认 300s）、`KB_MINERU_TIER`（默认 `basic`）、`KB_MINERU_EXTRA_ARGS`。 |
| **依据** | 实测 `uv pip install --dry-run mineru --python C:/python/python.exe` 会把 **starlette 0.52.1 → 1.10.0**、pydantic 2.12.3 → 2.14.1 —— 直接破坏 FastAPI 后端。隔离安装是唯一安全路径（与 OfficeCLI 同模式）。 |
| **强制细节** | PDF 必须显式 `--pages all`（默认只解析前 10 页，静默丢内容）；输出目录用任务临时目录，仅取 md；超时/非零退出 → 走兜底并记日志。 |

## 裁定 6：审核通过时的落盘顺序与回滚

```
校验（字数 ≥1000 / 清洗 / 查重）→ 生成 md（首行标题 + 来源小字）
→ 写 `knowledge_src/{type}/.tmp_{uuid}.md`
→ 单文件入库（doc=stem、source=相对路径、metadata 带 contrib_id/origin）
→ 入库成功 → rename 为最终文件名 → 更新 DB（已入库、md_path、chunk_count、convert_by）→ 通知
```

任一步失败：删除临时文件、DB 保持"待审核"、返回 502/422 并给出原因；**绝不出现"文件在目录里但库里没有"或反之**。
**依据**：现状是"先写库、无文件"，迁移后必须双向一致；research §7.2 已记录该风险。

## 裁定 7：Agent 身份 —— 新表 `agent_clients`，不建 `users` 行

| 项 | 内容 |
|---|---|
| **裁定** | 新建 `agent_clients(id, name, api_key_hash, model, owner_user_id, scopes, enabled, created_at)`；内置一条 `knowledge_scout`（scout 采集器）。贡献表加 `source_kind(user\|agent)`、`source_agent_id`、`origin_urls(JSON)`、`origin_filename`、`md_path`、`convert_by`；时间线加 `actor_kind(human\|agent)`。 |
| **认证** | 进程内（聊天工具）直接带 Agent 身份调用 service；外部 HTTP 用 `X-Agent-Key`（哈希比对 `api_key_hash`，`scopes` 限 `contrib:submit`）。 |
| **依据** | 现有认证只有用户名+密码→JWT，`timeline.operator_id` 是 `users` 外键；不建 user 行才能在审计上真正区分"人 vs Agent"，且不改 `users` 表既有字段语义（00/01 的约束）。 |

## 裁定 10：Agent 网搜 —— Playwright 自由浏览 + 异步任务 + 硬边界

| 项 | 内容 |
|---|---|
| **形态** | Agent **自行搜集 → 自行总结 → 写成 md**（不是只登记缺口），产物走裁定 8 的审核流。方法论作为"采集手册"逐步沉淀：优先站点、具体网址的交互步骤、黑名单、失败原因。 |
| **触发** | 回答**结束落库后**异步触发（不阻塞 SSE）；触发信号 = 本轮"检索无命中"或"充分性判定 + 补检后仍不足"（与 Redis 会话缓存不足严格区分）。 |
| **工具** | Playwright（本机已装 Chromium）；单任务限额：站点 ≤ `KB_FETCH_MAX_SITES`(3)、页面 ≤ `KB_FETCH_MAX_PAGES`(8)、单页 ≤ 5MB、总下载 ≤ `KB_FETCH_MAX_BYTES`(8MB)、总时长 ≤ `KB_FETCH_TIMEOUT_S`(600)。 |
| **硬边界** | 禁 `file://`、`localhost`、内网段与保留 IP（防 SSRF），可配 `KB_FETCH_DENY_HOSTS`；越界直接拒绝并记 `agent_runs`。 |
| **可回放** | 新建 `agent_runs(id, conversation_id, gap_question, urls(JSON), model, methodology_version, result_md_path, contrib_id, status, created_at)`，每次采集一条。 |
| **依据** | 用户 2026-10-26："允许 Agent 用 Playwright 自由浏览任意站点，这也是方法论设计的目的原因"；时延/并发约束来自 01 口径与 research §7.4。 |

## 裁定 13：验收口径

1. **转换**：9 份 PDF + 2 份 docx 全部产出 md；含表格的样本表格保留（MinerU 路径）；MinerU 不可用时兜底仍能出 md 且标 `fallback`。
2. **门槛**：清洗后 <1000 字的贡献被拒；≥1000 字通过。
3. **查重**：同名/同标题提交 → 审核界面标红，驳回理由含"标题重复"。
4. **落盘一致性**：通过后 `knowledge_src/{type}/{stem}.md` 存在、`kb/list` 能列出、`kb/doc` 能打开、检索能命中、`references` 显示文件名而非 `contrib_id`。
5. **失败回滚**：模拟入库失败 → 目录无残留临时文件、状态仍"待审核"。
6. **Agent 提交**：`knowledge_scout` 产物进待审核、`source_kind=agent`、`agent_runs` 有记录、管理员可见 URL 清单。
7. **方法论**：`GET/PUT/regenerate` 可用；`Methodology.md`/`cases.md` 不出现在 `git status`；`.example` 存在。
8. **网搜**：真机跑通 1 个站点（含黑名单拦截与越界拒绝用例）；回答时延无回归（异步触发）。
9. **旧块清理**：`--dry-run` 报告准确，`--apply` 后 `contrib_1` 块为 0。
10. **回归**：`test_knowledge_contrib.py` + 新增用例全绿；01/03 的问答链路不受影响。
