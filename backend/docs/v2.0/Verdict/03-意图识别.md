# 03 意图识别（回答前门禁）· 裁定

> 裁定只写结论与依据；方案正文在 `../v2.0规划文档.md` §03，调研证据在 `research/03-意图识别.md`。
> 本轮裁定依据：2026-10-24 用户拍板（纯 LLM 判定 / 带上一轮问题 / 检索失败降级并入）+ 同日调研实测。

---

## 裁定 1（2026-10-24）：判定方式用**纯 LLM 单次二分类**，不做规则快路径

| 项 | 内容 |
|---|---|
| **分叉** | ① 规则快路径 + LLM 兜底；② 纯 LLM 单次分类；③ 纯规则；④ 交给 Agent 自判。 |
| **裁定** | **②**。每轮回答前**一次** LLM 调用，专用提示词 `chat_intent`，`temperature=0`、`max_tokens=80`、超时 **8s**，只输出一行 JSON `{"intent":"chat|knowledge","reason":"..."}`。代码里**不做关键词短路**。 |
| **依据** | 用户 2026-10-24 明确选"纯 LLM"；实测单次中位 **0.98s**（min 0.57s / max 7.45s 首调建连），落在追问基线 15~20s 的噪声内；单条成本可忽略；维护面比"规则 + 兜底"少一半（不会出现词表腐化）。 |
| **代价（已知）** | 每轮多一次模型调用；模型抖动时判定结果不稳 —— 由裁定 4 的保守回退吸收。 |
| **显式免检索指令** | 不写代码规则，由 `chat_intent` 提示词承担：用户说"不用检索/别查资料/不用知识库/凭经验"时判 `chat`。 |

---

## 裁定 2（2026-10-24）：判定输入**必须带上一轮问题**，避免指代句误判

| 项 | 内容 |
|---|---|
| **问题** | 调研实测：「第一问」被判成 `chat`（句中无任何业务词），而它实际是在追问上一轮回答里的条目。 |
| **裁定** | `detect()` 输入 = **当前问题** + **上一轮 user 问题全文** + **上一轮 assistant 回答前 200 字**（都没有则只给当前问题）；总注入长度上限 `CHAT_INTENT_MAX_HISTORY_CHARS=600`，超出按"上一轮问题优先"截断。 |
| **依据** | 指代型追问（"第一问""那…呢""刚才说的那个"）在不看上下文时不可判；带上一轮后模型能把它落到 `knowledge`。 |
| **边界** | 只带**最近一轮**，不做多轮摘要（多轮摘要会引入二次 LLM 成本，且与本任务无关）。 |

---

## 裁定 3（2026-10-24）：闲聊走**独立直答路径**，跳过预处理、检索与 Agent

| 项 | 内容 |
|---|---|
| **裁定** | 判 `chat` 时：`mode="chat"` → 不调 `query_preprocess`、不调 `retrieve_queries`、不起 `chat_agent`；直接用 `llm_client.chat_stream` + 新场景 `chat_assistant`（身份/能力/边界提示，注入最近 3 轮对话，**不注入知识库资料**）。 |
| **副作用约束** | ① 消息照常写 `chat_messages`（否则上下文断裂）；② **不写会话 RAG 缓存**（不 `put_blocks` / 不 `touch`），避免污染后续追问的 covered；③ `references` 为空、不 `_merge_sources()`、不显示来源条。 |
| **依据** | 闲聊没有知识诉求，检索纯浪费（首问 5~45s）；走 Agent 还要多一次规划调用。 |
| **前端** | 状态行新增"闲聊（未检索）"一档；`mode` 枚举从 `full/cache/incremental/context` 扩为 5 档（新增 `chat`）。 |

---

## 裁定 4（2026-10-24）：判定失败 / 输出不可解析 → **保守回退知识问答**

| 项 | 内容 |
|---|---|
| **裁定** | 以下任一情况一律按 `knowledge` 继续既有链路，并在 `refs.intent` 与 `meta` 标 `degraded={kind:"intent"}`：LLM 超时（>8s）、抛异常、输出非法 / 缺 `intent` 键 / 值不在枚举内。 |
| **依据** | 误判方向代价不对称：**知识题被判闲聊 = 无依据直答（安全领域不可接受）**；闲聊被判知识 = 只慢几秒。 |
| **日志** | `WARNING` 一行，含异常类型与截断后的模型输出（≤120 字），不含任何凭证。 |

---

## 裁定 5（2026-10-24）：**检索失败降级**并入本次，不再让整轮回答 500

| 项 | 内容 |
|---|---|
| **触发事实** | 2026-10-24 用户那次问询：预处理失败已按设计退回原话，但随后 `retrieve_queries` 抛 `OSError: [Errno 22] Invalid argument: '.env'`（盘掉线导致 CWD 失效），`_prepare()` **无兜底** → ASGI 500、SSE 断流、整轮回答丢失。 |
| **裁定** | `_prepare()` 内的检索段（`retrieve_queries` / `retrieve_more` 及向量库初始化）统一包一层：**任何异常** → `context=""`、`blocks=[]`、`degraded={kind:"retrieval", reason:"..."}`，**继续生成**；system 侧追加一句"本轮资料检索失败，只能依据通用知识回答，并明确告知用户未引用知识库"。 |
| **反向约束** | 降级**不得**伪造来源：`references` 为空、`sources` 为空，前端显示"未引用知识库（检索失败）"。 |
| **依据** | 用户 2026-10-24 决定"并进本次"；问答的可用性优先于"必须有引用"，但必须让用户看见降级事实。 |

## 裁定 6（2026-10-24）：可观测与审计口径

| 项 | 内容 |
|---|---|
| **落库** | `chat_messages.references` 中新增 `intent`：`{label, reason, ms, model, degraded}`；与既有 `preprocessed` 并列，**不动 `database/schema.sql`**。 |
| **审计接口** | `preprocess_audit.build_rounds()` 追加 `intent` 字段；闲聊轮没有 `preprocessed`，`collect()` 不再当异常数据丢弃，改为展示"判定：闲聊（未检索）/ 耗时分秒 / 理由"。 |
| **SSE meta** | 增加 `intent`、`intent_ms`、`intent_source="llm"`、`degraded`；闲聊轮 `sources=0`。 |
| **前端** | ① 状态行 5 档（含"闲聊（未检索）"）；② 🔎 面板多一行"意图";③ 检索降级时状态行显示"检索失败 · 通用回答"。 |

## 裁定 7（2026-10-24）：配置与回滚开关

| 配置 | 默认 | 说明 |
|---|---|---|
| `CHAT_INTENT_ENABLED` | `True` | 关闭 = 完全跳过判定（全部按 knowledge），**等于回到现状**，用于紧急回滚 |
| `CHAT_INTENT_TIMEOUT` | `8.0` | 单次判定超时（秒），超时按裁定 4 回退 |
| `CHAT_INTENT_MAX_HISTORY_CHARS` | `600` | 注入判定的历史文本上限 |
| `CHAT_INTENT_MAX_TOKENS` | `80` | 判定输出上限（够输出一行 JSON） |

提示词新增两个场景：`chat_intent`（分流）、`chat_assistant`（闲聊直答的身份/能力/边界）。

## 裁定 8（2026-10-24）：验收口径

1. 判定准确性：调研样本 11 条（含带上下文的「第一问」）**≥10/11**；且**0 条业务题被判 `chat`**。
2. 闲聊首字时延：判定 + 首字 **≤5s**（不含模型冷启动）。
3. 知识问答**无回归**：抽 4 条跑通，`references` 与来源标签与 01 基线一致。
4. 闲聊轮**不写** `shudao:rag:conv:*`（Redis 侧可验证）。
5. 判定失败（断网/超时）→ 走 knowledge 且 `refs.intent.degraded.kind="intent"`。
6. 检索失败 → SSE **不 500**，回答完成、`degraded.kind="retrieval"`、`references` 为空、前端有提示。
7. `pytest tests/test_intent_gate.py` 全绿（判定解析、历史注入、闲聊不写缓存、失败回退、降级），既有 `test_agent_cache.py` / `test_ppt_agent.py` 不回归。
8. `CHAT_INTENT_ENABLED=false` 时行为与 01 收官版本一致（回归开关有效）。
