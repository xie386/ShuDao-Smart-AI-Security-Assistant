## 二、检查方法

1. **代码审计**：`src/routers/*.py` + `src/services/*.py` + `src/main.py` 静态挂载，逐个端点看鉴权依赖与归属过滤。
2. **运行时交叉验证**：用 `create_access_token` 给数据库里两个真实账号签发 token（A = user 186，B = user 17），用 `TestClient` 在进程内交叉请求三个模块。
   - 只发 GET；唯一一次写请求（改他人大纲 / 导出他人试卷）**被 403/404 拦下，无副作用**；
   - 没有新建账号（遵守「单测/探针不得向真实库建号」的纪律，见 deep_search_pro `文件存放规则.md` §四）。
3. **数据侧对照**：直接查 `ppt_tasks` / `exam_papers` / `conversations` 三张表的归属分布，验证「谁拥有什么」。

## 五、数据事实（只读查询）

```
conversations：按 user_id 分布，每个账号各自持有（尾部样本 608/615/616/650/…/834 各 1 条）
ppt_tasks：共 6 行 —— user 186 有 1 行（临时用电安全，已完成）；
           user 17 有 5 行，其中「安全生产法要点」出现 3 次（id=8 已完成、id=9/10 草稿）
           file_path 分布：ppt_files\临时用电安全.pptx / 隧道施工安全.pptx / 高处作业安全.pptx / 安全生产法要点.pptx
exam_papers：共 1 行 —— user 17，paper_d0fd10a7c52c，file_path=exam/paper_d0fd10a7c52c.md
磁盘：ppt_files/ 有 3 个 pptx（8月17 生成）；uploads/exam/ 有同一条试卷的 md/docx/pdf 三份
```

**由数据得出的关键推断**：同一账号内已出现「同主题多条任务」（id=8/9/10）。若把 id=9 触发生成，`dest` 与 id=8 同名 → **直接覆盖已完成任务的产物**；换成两个账号，就是跨账号覆盖。

## 六、发现清单（只列观察，不定方案）

| 编号 | 观察 | 硬证据 | 风险面 |
|---|---|---|---|
| ISO-1 | PPT 产物文件名仅由主题决定，落全局命名空间 | `ppt_service.py:153-154` + `ppt_tasks` 同主题 3 行 | 跨任务/跨账号覆盖；删任务误删他人文件 |
| ISO-2 | `/ppt-files/*` 静态无鉴权，主题名可猜可枚举 | `main.py:135` + 实测 200 拿到 16.2MB | 已登录/未登录任何人都能取他人 PPT |
| ISO-3 | 试卷导出文件经 `/exam-files/*` 与 `/uploads/exam/*` 双无鉴权通道可取 | `main.py:141,123` + 实测 200 | 弱（paper_id 为 uuid4 hex[:12]，不可枚举，需 URL 泄漏） |
| ISO-4 | 用户上传的 PPT 模板对全部账号可见、可用 | `ppt_template_service.py:88-102`（`list_templates()` 不按 user 过滤） | 已按 `../Verdict/00-账号隔离性前置检查.md` 裁定 3 处理：属有意共享的团队模板库 |
| ISO-5 | `routers/exam.py` docstring 端点数量与实际不符 | `exam.py:3-9` | 无（文档瑕疵） |
| ISO-6 | 全量 pytest 不收敛：7 个用例后挂起超 300s | 实测 `pytest tests/ -q` 超时 | 影响回归策略（本大点只跑相关子集） |

## 八、路线考察（含被否与暂缓）

| 路线 | 内容 | 状态 |
|---|---|---|
| R1 只改名不鉴权 | 文件名加 `u{uid}_t{tid}_` 前缀，静态目录照旧公开 | 否（解决覆盖、不解决越权） |
| R2 只鉴权不改名 | 加下载端点、静态目录取消公开，但产物仍按主题命名 | 否（越权解决、撞名覆盖仍在） |
| R3 改名 + 鉴权端点 | 两者同批落地 | 采纳（见 Verdict 裁定 1） |
| R4 迁移历史文件 | 把 3 个 pptx + 1 套试卷搬进新目录并 UPDATE 字段 | 否（现网仅演示数据，迁移收益低于风险） |
| R5 试卷导出目录搬出 uploads | `uploads/exam/` → `exam_files/`（不再被 `/uploads` 静态暴露） | 采纳（见 Verdict 裁定 2） |
| R6 试卷历史目录处置 | 中间件对 `/uploads/exam/**` 返 403（不迁移）／搬文件并改库／放任 | 已落地为中间件方案（见 `../Verdict/00-账号隔离性前置检查.md` 裁定 6） |
| R7 下载授权的 token 传递 | fetch + Blob（token 只在 header）／`?token=` query（前端 2 行，token 进日志）／后端先行前端后补 | 已落地为 fetch + Blob（见 `../Verdict/00-账号隔离性前置检查.md` 裁定 5） |
| R8 模板按账号隔离 | `list_templates(user_id)` 只返本人上传 | 否（见 Verdict 裁定 3） |
| R9 顺带治理 pytest 不收敛 | 在本大点内排查全量挂起 | 暂缓（不属本议题，避免混入无关改动） |

## 九、探针与复跑

探针脚本为一次性只读工具，附在 `docs/v2.0/research/` 之外的临时目录（未入库）。核心逻辑可复现：

```python
# 1) 给真实账号签发 token（不建号、不改数据）
from src.core.security import create_access_token
tok_a = create_access_token(186, "employee"); tok_b = create_access_token(17, "employee")
# 2) 进程内交叉请求
from fastapi.testclient import TestClient
from src.main import app
c = TestClient(app)
c.get("/api/ppt/6", headers={"Authorization": f"Bearer {tok_a}"})        # 期望 403
c.get("/ppt-files/高处作业安全.pptx")                                      # 期望（改造后）401/404
c.get("/exam-files/paper_d0fd10a7c52c.md")                                # 期望（改造后）401/404
c.get("/uploads/exam/paper_d0fd10a7c52c.docx")                            # 期望（改造后）403
```

改造前实测输出已逐条记录在 §三（本文即证据源）；改造后应逐行反转，验收口径见 `../v2.0规划文档.md` §00 ③ 段。
