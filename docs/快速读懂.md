# 蜀道智能安全助手 — 快速读懂

> 一个面向 **交通建设企业安全生产管理** 的 AI 平台项目，覆盖 **隐患排查闭环（H）**、**智能安全问答 RAG（A）**、**安全讲座 PPT 智能制作（P）** 三大模块，基于 `Python FastAPI` + `Vue3` + `MySQL` + `Redis` + `Chroma` 构建。
> 当前为 **D1（基建日）状态**：后端分层脚手架 + 认证模块已实测可用，隐患/AI/PPT 模块代码尚未开工（详见文末「项目现状」）。

---

## 一、项目简介

蜀道集团的传统安全管理依赖纸质/表格流转：隐患上报不及时、整改闭环难追踪、安全培训资料分散。本产品用 AI 技术把三件事线上化：

- 🚨 **隐患安全模块（H01–H08）**：隐患「上报 → 派单 → 整改 → 验收」全流程闭环，含图片、定位、等级分类、统计分析、消息通知；
- 🤖 **AI 助手模块（A01–A07）**：基于企业安全知识库的智能问答，**RAG 架构** + SSE 流式输出 + 回答引用来源 + 点赞/踩反馈；
- 📊 **PPT 工坊模块（P01–P08）**：输入主题 → AI 生成大纲 → 用户编辑 → AI 填充内容 → 3 套模板渲染 → 导出 `.pptx`。

它的核心理念是 **「文档先行 + 分层后端 + RAG 增强」**：

- 所有需求以 **H/A/P 功能点编号** 贯穿五份文档，验收时逐号打勾；
- 后端严格分层 `router → service → model/schema`，接口契约先行，四人并行不打架；
- AI 回答**必须基于企业知识库**，用「结构感知分块 + 混合检索 + 重排」压住幻觉。

> 一句话总结：把「纸质台账里的隐患」变成「线上闭环」，把「翻制度查规范」变成「问 AI 秒答」，把「手工做培训课件」变成「AI 一键生成」。

## 五、📖 阅读指南（建议顺序）

这个项目是**按「题目 → 产品 → 架构 → AI → 排期 → 配置 → 安全 → 模型 → 业务 → 入口」的难度递进**组织的。建议按下面的顺序读，每读一个文件都先问自己一个问题：

| 顺序 | 文件 | 看什么 / 思考题 |
| --- | --- | --- |
| 1️⃣ | `项目任务书-蜀道安全助手.md` | **先读「题目」**。功能点分 H/A/P 三组、评分权重 30/25/20/15/10。理解：哪些功能是 P0 必做？为什么「文档质量 25%」比「代码质量 20%」还重？ |
| 2️⃣ | `docs/PRD.md` | **产品视角**。隐患状态机「待处理→处理中→待验收→已闭环」+「已驳回→重新处理」。理解：为什么需要"已驳回"这个状态？谁有权限派单/验收？ |
| 3️⃣ | `docs/ARCHITECTURE.md` | **技术视角**。FastAPI 分层 + RAG 服务 + 数据层。理解：任务书写 Spring Boot，为什么实际换 FastAPI？router/service/model 三层的边界在哪里？ |
| 4️⃣ | `docs/AI_SOLUTION.md` | **AI 视角**。模型选型、四段式 Prompt、RAG 架构。理解：为什么纯向量检索不够，要「稠密+BM25+RRF+重排」混合检索？分块为什么被称为"RAG 质量的第一道关卡"？ |
| 5️⃣ | `docs/里程碑技术书.md` | **执行视角**。4 人 × 5 天任务矩阵，四线并行。理解：为什么前端/测试用 vibe coding 而不排主线人力？「接口契约先行」解决什么问题？ |
| 6️⃣ | `backend/src/core/config.py` | **配置**。pydantic-settings 读 .env。理解：模型名（deepseek-v4-flash / agnes-2.5-flash / qwen3.8max）为什么不硬编码在代码里？ |
| 7️⃣ | `backend/src/core/security.py` + `db.py` | **安全+数据**。bcrypt 哈希、JWT 签发。理解：为什么注册接口不接受 role 字段（硬编码 employee）？bcrypt 和 passlib 的兼容坑是什么？ |
| 8️⃣ | `backend/src/models/user.py` | **模型**。对齐 P3 已建的 users 表。理解：表是谁建的？为什么应用启动时不自动建表（create_all）？ |
| 9️⃣ | `backend/src/services/auth_service.py` + `routers/auth.py` | **业务+路由**。注册/登录/签发三层配合。理解：为什么 router 里不能写业务逻辑？统一 401 不泄露账号存在性的设计意图？ |
| 🔟 | `backend/src/main.py` + `tests/` | **入口+测试**。lifespan 里不建表；6 个测试覆盖认证闭环。理解：TestClient 测试依赖什么环境（MySQL 必须可连）？ |

> 💡 学习心法：**蜀道项目 = 文档定需求（H/A/P 编号一致）+ 后端分层（config→models→schemas→services→routers）+ AI 增强（结构分块→嵌入→混合检索→重排→生成）+ 部署交付（Docker 五服务）**。把这条主线记牢，任何功能点都能顺着「编号 → 文档 → 代码」找到位置；发现编号对不上，就是文档过期了。
