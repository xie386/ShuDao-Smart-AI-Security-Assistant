AI 问答 Agent

chat_agent · LangChain create_agent · 工具 1 个
  • 前置门禁：意图识别先判闲聊/知识，闲聊直答不检索（避免答非所问的成本）。
  • 理解：陈述句化、语义专业化、多主题拆分（上限 2 条）、剔除已检索项。
  • 检索：子块级混合检索（向量 + BM25）+ 重排 fp16，会话级缓存滑 TTL。
  • 工具：retrieve_more 补检，代码硬拦“至少调用一次”，不靠模型自觉。
  • 输出：流式 SSE + 引用来源；检索失败降级直连 LLM 并显式标注“未引用”。
src/ai/intent.py · query_preprocess.py · sufficiency.py · rag.py · chat_agent.py · routers/chat.py

知识贡献 Agent

agent_scout · Playwright 采集 · 人审后入库
  • 触发：回答自述“资料不足”或调用缺口上报，不靠人工点按钮。
  • 采集：多引擎配置化（360 → 搜狗 → Bing）、来源质量分级、SSRF 硬边界。
  • 闸门：关键词相关 + 条款级证据 + 知识含量（≥1000 字 / ≥3 出处 / ≥5 条），不足输出 INSUFFICIENT 而不是凑字。
  • 产出：纯知识正文 md（来源以小字保留），提交管理员审核；通过后落 knowledge_src 四类并增量入库。
  • 审计：agent_clients / agent_runs 记录每次运行，案例库双向回写审核结论。
src/ai/agent_scout.py · services/knowledge_contrib_service.py · agent_docs.py · kb_govern.py

PPT 生成 Agent

ppt_agent · S0–S8 混合式编排 · OfficeCLI 唯一写者
  • 阶段：S0 预处理 → S1 取据 → S2 判定 → S3 补检 → S4 大纲 → S5 素材 → S6 逐页制作 + 自检 → S7 校验 → S8 落盘（S2/S3/S6/S7 在 Agent 内部，图上只画对外调用）。
  • 分工：代码管阶段与几何（版式坐标由代码算），模型只管每页文字与配图意图。
  • 工具：OfficeCLI 建/批处理/截图/校验/释放文件；AGNES 只做版面四类问题审图；Unsplash 配图。
  • 隔离：每账号每任务一个沙箱目录；进度走 SSE 且落 jsonl，断线可回看。
  • 兜底：OfficeCLI 缺失时回落内置 ppt_local，不让整单失败。
src/ai/ppt_agent.py · ppt_layout.py · ppt_tools.py · ppt_service.py · core/paths.py

隐患识别 Agent

hazard_agent · 视觉 + RAG + 缺口补料 · SSE 四阶段
  • 视觉：qwen3.7-plus 出隐患（类别/等级/描述/坐标），坐标归一化到原图，随后进入编排。
  • 检索：每条隐患并发检索（8s 超时），Top1 < 0.65 判定“知识库无依据”。
  • 补料：缺口合并成一次网搜（复用贡献 Agent 的采集链路，70s 硬超时），同时提交知识文件审核。
  • 汇总：一次 LLM 写建议，引用必须能对上证据（库内 doc·章节 / 网络主机），对不上就不写建议。
  • 呈现：前端 SVG 叠加（类别定色相、等级定深浅、聚焦淡化），服务端烘焙 JPG 存 hazard_ai_analysis。
src/ai/hazard_agent.py · vision.py · utils/boxes.py · core/box_style.py · services/hazard_analysis_service.py

辅助智能体

intent · review_preview · vision_agent
  • 意图识别：纯 LLM 单次二分类，8s 独立超时，失败一律退回“知识问答”（误判代价不对称）。
  • 审核预筛：给管理员出参考意见，只读不写库，避免 AI 直接改审核结论。
  • 视觉审图：AGNES 只看截图，只回答溢出/遮挡/对比度/缺失四类问题，失败按 skipped 处理。
